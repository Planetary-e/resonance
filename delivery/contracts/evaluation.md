# Evaluation contract

## Evaluation objectives and release thresholds

The 20 definitions in `delivery/evals/cases.json` specify expected evidence only; none has been executed in this session. Every K1–K8 gate remains open. Blocking cases must pass on the same frozen integrated candidate before FEAT-011 can recommend a release decision. A safety violation blocks regardless of averages.

The binding thresholds are exactly those in `docs/developers/v0.4-acceptance-kpis.md` and PRD-001–PRD-008. In particular: K1 >=99.5% good nominal operations, local warm p95 <=6 s, impaired p95 <=8 s/p99 <=10 s and zero duplicate notices; K2 zero listed safety failures in >=1,000 varied faults, recovery p95 <=5 min and 100/>64 cycles within original caps; K3 100 transitions and connected update p95 <=60 s with strict cutoff; K4 >=95% automation, <=2% false exclusion, <=1% false inclusion, <=10% equal-rights grant difference and no 100-identity quota amplification; K5 Recall@5 >=90%, notified precision >=80%, FPR <=5%, <=5-point rotation loss and <=5% identification in each attack; K6 per-declared-attack AUC <=0.55 separately in busy/sparse/colluding scenarios with direct-observation prohibitions; K7 memory/CPU/power/network limits as specified; K8 14 days, >=5 independent operators, >=3 networks and >=99% wall-clock availability. No variance may relax a target. Threshold-straddling 95% confidence intervals are inconclusive.

Existing failures remain baseline evidence: K5 real-text reconstruction 86–97% and known-text 100%; K6 cooperating-hop linkage 32/32. The 13/13 focused, 46/46 composed and noEmit evidence is limited to the accepted finite recovery slice. RSO3/RSO4 remain rejected.

## Evaluation data

Use non-sensitive synthetic fixtures for protocol faults, authorization negatives and adversarial transport. K5 requires independent Spanish/English held-out relevance labels, >=1,000 queries and >=10,000 publications; labels must not be generated by the embedding under test. Development and test topics/paraphrases remain separate; unjudged cross-pairs are not negatives. Freeze attack training/test splits by session/user and withhold trial boundaries unavailable to real observers.

K4 requires independently labeled eligible/ineligible adversarial data, declared eligibility provenance, attacker control and independent-claim acquisition cost. K6 declares observer views, compromised roles, auxiliary knowledge, candidate population, chosen-query opportunity and observation window before execution.

Real personal data requires explicit consent and a reviewed handling plan; do not place raw text, keys, embeddings, channel plaintext, unredacted network metadata or other sensitive content in `delivery/`. Result records contain sanitized aggregates and paths to appropriately protected evidence only. Holdout identities and corpus/model/config hashes are recorded without publishing restricted material. Refresh or expansion requires predeclared change control and cannot replace an unfavorable frozen baseline retroactively.

## Deterministic and end-to-end evaluation

Prefer schema, exact-state, signature, cutoff, retry/dedupe, physical-byte, resource and negative authorization assertions. Use real interfaces for integrated publish/search/mailbox/consent/recovery paths. Fault manifests include process death during persistence, lost replies, partitions, stale restores, corrupt input, exhausted reservations and competing writers; repetition of one happy path does not qualify.

K1 uses >=1,000 submitted operations per local/impaired profile across three independent executions with balanced publish/search/mailbox reporting, cold/reconnect/warm connections and frozen seeds. Impairment is 50 ms base RTT, independent +/-5 ms per-direction variation and independent 1% packet loss each way below TCP. Good operations require correct durable acknowledgement within the original deadline; retries and failures are charged.

K2/K3 preserve five pinned members, quorum four, at most one Byzantine, original C=262144/L=65536/P=65536/D=524288/F=32768, 2 GiB aggregate storage, 512 reservation entries, independent 1 MiB serialized metadata, 256 MiB cumulative reconstruction/copy work, 3 s live and 30 s offline limits. New 100/>64 execution is permitted only after a complete, preflighted, independently reviewed new path; never rerun the stopped frozen100 campaign.

K7 measures the complete relevant process tree, >=30-minute sustained/idle windows, physical incremental power against a matched baseline, and every physical edge once per direction including TLS/discovery/issuance/maintenance/failures. Cold model initialization is reported separately and in lifecycle totals. No concurrent host workloads are allowed during resource qualification.

## AI and subjective evaluation

AI scope is local `nomic-ai/nomic-embed-text-v1` 768-dimensional inference through Transformers.js/ONNX, followed by deterministic rewrite/512-bit LSH/Hamming behavior. There is no hosted LLM and no AI eligibility decision. Model/revision/tokenizer/ONNX/runtime/cache provenance is frozen and recorded; first-download and warm paths are separated. No unreviewed provider or model substitution is allowed.

Quality judgments use independently labeled held-out data and deterministic metrics, not an LLM judge. Manual accessibility, documentation-claims, legal/deployment and security reviews use explicit rubrics in EVL-017/018/020 and named qualified human reviewers. Calibration means reviewing ambiguous examples against the rubric before acceptance; model confidence is not evidence. Repetitions and run-to-run variance follow the frozen experiment, with 95% confidence intervals where applicable.

## Execution and evidence policy

All case commands are null because these are future qualification procedures and this session is artifact-generation only. Before execution, the responsible feature freezes an exact command/procedure, environment, seeds, candidate identity and result destination. No product test, campaign, build, installer, network deployment or external action is authorized by these definitions.

Each run records actual command/procedure, start/end, full working-tree/source/data/model/config/dependency identity, hardware/OS/runtime, failures, limitations and sanitized evidence. `delivery/results/RUN-*.json` outcome is `passed` only if every required check passed with complete evidence; otherwise use `failed` or `blocked`. Unrun cases are not result records. Generation and independent acceptance remain separate for protocol-critical, privacy, security and release decisions.

## Regression and change control

Preserve failed screens and rejected candidates as baselines. Never weaken/delete a case, threshold, trust assumption, corpus, attack or resource charge to obtain a pass. Flaky results are unresolved and require a frozen reproduction, not selective reruns. Pre-existing failures remain visible and cannot be relabeled as new passes.

Re-evaluate affected cases after source, model, tokenizer, dependency, configuration, protocol, data, packaging, threat-model or deployment changes. FEAT-011 requires rerunning the complete gate set on the frozen integrated candidate. Any scope/threshold change requires explicit owner decision; legal/compliance control changes require the responsible human reviewer.
