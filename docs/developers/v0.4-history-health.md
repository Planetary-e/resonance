# Local aggregate history health

Status: opt-in runtime and desktop telemetry, 2026-10-17. The authenticated relay
`/stats` response includes `history`; the authenticated desktop relay-status API
projects it onto known aggregate fields. Public health/discovery responses do not
publish it. These observations never establish a current remote quorum.

## Reported observations

| Role | Local observation | What it does not establish |
| --- | --- | --- |
| Protected owner | Admission initialized, operation in progress, retained pending update, current-generation archive block/byte usage and limits | Current remote copies, latest external generation or complete on-disk integrity |
| Policy observer | Listener startup/draining, current local policy validity, retained conflict/recovery fence, pending update and current-generation block/byte usage | Latest external policy, current remote copies or permission to sign the next observation |
| Enrolled volunteer | Opened generations and limit, retained/staged blocks, encrypted payload bytes, manifest reservations and current-generation limits | Actual total disk use, accepted state of other members or physical power-loss durability |
| History transport | Configured member/bridge/controller counts, connected direct members/bridges/targets, charged operations and transfer-buffer reservations | Target connectivity beyond a bridge or four fresh durable acknowledgements |

The owner's transport explicitly reports zero direct member connections when all
five members route through one connected bridge. The bridge's own target count
is a local observation, not something the owner can substitute for signed
receipts. No topology is collapsed into one durability member.

Each role is absent, starting, available or unavailable. A failed/closed role
reports unavailable instead of zero usage. Exception strings, paths, keys, root
and envelope IDs, token/spend/request bindings, per-peer lists and per-peer activity
are omitted. The desktop validates nonnegative integer counters and booleans,
strips unknown fields and preserves unknown/unavailable status. It refreshes local
stats every five seconds only while the GUI is unlocked and relay mode is enabled.

## Storage accounting and limits

Owner archive counters cover its retained **current generation** ciphertext only.
They exclude its policy/spend image, writer journal, old ancestry and recovery
workspace. A pending update remains reported even when replication fails; reading
status neither completes it nor silently retries it.

Volunteer payload counters sum the opened enrolled generation stores, including
their staged selected-history blocks. Each store reserves two maximum manifests
(4 MiB), so `reservedBytes` is encrypted block bytes plus these reservations.
The current generation's reservation and block count are compared with the
operator's configured per-generation caps. The existing combined ancestry ceiling
and maximum generation count remain in force. These counters exclude successor
provisioning journals, unpublished child staging, temporary files and filesystem
overhead. They must not be labeled total disk usage or a complete combined quota.

Stats use cached scalar accounting and bounded generation/connection collections.
The observer copies its bounded current writer record to select cached authenticated
state; it does not copy policy contents or conflict evidence into telemetry.
Stats do not decrypt payloads, traverse every ciphertext file, sign requests,
write history or probe the network. They are operational observations of the open
process; a fresh integrity audit or network receipt exchange is a separate action.
Transfer-buffer reservations likewise exclude JSON objects, cryptographic work
and native allocations, and do not measure total process memory.

Existing resource controls still gate new storage/forwarding. Lowering a retained
history's explicit configuration below its existing bounds refuses reopening;
it never deletes accepted state. Reviewed owner/volunteer limit editing and desktop setup/recovery now have
separate workflows. A [bounded offline filesystem inventory](v0.4-combined-storage-budget.md)
measures saved runtime/history/workspace roots on demand. Cross-role write
reservation and a combined enforced budget remain open. The publication-storage control must not be
presented as the history's complete storage budget.

## Evidence

Tests check aggregate retained-byte/block accounting across three generations and
reopen, owner startup and accepted writes in real Node processes, bridge topology
without a false direct-member count, disconnect/close, strict untrusted status
projection and missing/failed observations. The desktop explains pending work,
separate connection observations and unknown status without displaying private
identifiers or claiming a live quorum. Existing four-copy durability and refusal
rules are unchanged.

Observer-only relays also show contribution health. Before the observer's initial
four-copy check finishes, its role reports `starting` even if the ordinary relay
listener already accepts connections. A ready listener does not cache a quorum
claim: every observation still requires four fresh history responses. Policy
expiry is evaluated against the current clock on each status read. The optional
observer field is omitted by older/no-observer runtimes; malformed supplied fields
report unavailable instead of silently claiming healthy state.
