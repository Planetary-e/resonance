# Scheduled traffic: first TLS falsification stage

## Predeclared scope

The owner approved continuing the [scheduled-traffic study](v0.4-scheduled-traffic-envelope.md)
on October 18. Astra approved this bounded first stage before implementation or
measurement. It uses the same cumulative budget and candidate 2 /
`B-QUIET-COLLUSION`; neither the architecture counter nor K1–K8 restarts.

This stage can expose a transport failure. It cannot establish application
performance, anonymity, physical network cost or power compliance. It adds an
opt-in evaluator, with no change to application traffic or production defaults.

## Frozen experiment

One process hosts two authenticated loopback TLS edges and four directed lanes.
The existing public test CA and localhost certificate are confined to the
fixture, with normal hostname and certificate verification. Instrumentation
counts each logical edge once, before TLS termination.

| Session | Duration | Submission | Processing after complete request |
| --- | ---: | ---: | ---: |
| Idle | 12 s | None | None |
| Active, no processing | 12 s | 1.025 s | 0 ms |
| Active, fixed processing | 12 s | 1.025 s | 1,000 ms |
| Forced deadline control | 12 s | 1.025 s | 12,000 ms |

The last row deliberately exceeds the original deadline and must fail. It is
not an alternative processing budget or a latency candidate. Each operation
retains its original ten-second deadline, at session time 11.025 seconds.

All sessions use 125-ms slots, at most 768 useful bytes per cell, and a
1,024-byte allocation per direction and edge. The fixture payload is the
historical 15,495-byte request and 11,213-byte reply. Metadata and padding count
in addition to useful bytes. Dummy and real application cells have equal size.
No compression, operation-triggered connection, extra write or catch-up burst
is permitted. Received fragments become eligible only at a subsequent slot.
An overdue slot is skipped; bounded backpressure fails the session. Startup,
termination and enrollment are independent of operation activity in these runs.

Focused controls cover certificate rejection, byte-verified payload reassembly,
overdue-slot skipping, backpressure failure, and budget preflight refusal. The
forced-deadline control must cancel pending replies and timers. All failures
remain in the submitted denominator; unsuccessful latency is infinite, encoded
explicitly rather than as a successful finite percentile.

## Measurement boundary

Retain encrypted TCP-stream byte counts and timestamps, including handshakes
and shutdown, plus schedule lateness, CPU time and RSS. TCP data chunks are not
network packets. IP/TCP headers, ACKs, retransmissions and network-interface
energy are absent. A stream overrun can reject the allocation; a count below it
cannot certify physical-wire compliance. Other-edge bandwidth remains an
unimplemented allocation, not measured traffic.

The shared process does not supply per-role CPU or memory measurements, process
isolation, independent clocks, or volunteer availability evidence. These short
runs are diagnostic examples, not the K1 reference workload or sustained K7
resource qualification. The fixture is not the complete application protocol.

On this macOS host, `/dev/bpf*` is root-only and `powermetrics` requires
superuser access. No elevated capture or power measurement is part of this
stage. CPU usage is not watts; physical incremental-power validation remains
open even if CPU use is low.

The [existing cooperating-hop counterexample](../evals/private-adversaries-2026-10-18.md)
remains applicable as a design warning. Endpoint operators can retain forwarding
mappings. Equal padding or stream totals do not erase those mappings. This
stage produces no K6 AUC or collusion-privacy pass. Separate-process, burst,
reconnect, packet-loss, all-edge observer and physical-power tests remain open.

## Results

**The strict slot-allocation screen fails at the enrollment boundary.** All four
sessions observed 1,396 encrypted-stream bytes on edge 1, downward, in the first
session slot, above its 1,024-byte allocation. Later direction/slot bins contain
822 bytes. Post-handshake control traffic is a plausible explanation; the
retained metadata does not establish its cause. The first bin, startup and
shutdown remain included. Acceptable totals cannot erase this violation.

| Session | Completed / submitted | Operation latency | Total bytes, two TLS edges |
| --- | ---: | ---: | ---: |
| Idle | 0 / 0 | Not applicable | 323,848 |
| D=0 | 1 / 1 | 4,728.4 ms | 323,846 |
| D=1,000 | 1 / 1 | 5,728.1 ms | 323,847 |
| D=12,000 control | 0 / 1 | Infinite; original deadline | 323,848 |

Each session emitted 384 cells (96 slots times four lanes), with no skipped
slots or dropped trace entries. Completed operations verified every payload
byte. The forced-deadline case sent only the request's 42 cells across its two
edges and never released the reply; no real write occurred at or after 11.025 s.
These are single examples, not p95 estimates. TLS arrives within a slot here;
the offline model used slot-end arrivals, so these numbers are not direct
replications of its latency values.

The fixture uses an 800-byte application frame: up to 768 useful bytes and 32
bytes reserved for metadata/padding, with zero padding replacing unused useful
space. The observed ordinary TLS-stream increment is 822 bytes. The difference
between this and the 1,024 allocation remains unverified physical-wire headroom.
Aggregate stream totals differ by up to two bytes, including startup; equal
cell sizes must not be described as identical complete network transcripts.

Combined-process CPU time was 160–205 ms per approximately 12.1-second run;
sampled RSS peaks were 92.2–96.6 MB. These include all fixture roles and
instrumentation, have no unenrolled baseline, and cannot be assigned to client
or relay power budgets. No watts or sustained idle-CPU result is claimed.

Root and Astra review found a deadline ordering error before the measurement:
an overdue tick could run before the cancellation timer. The corrected code
checks a shared monotonic deadline before enqueueing, processing and each real
write, cancels the processing timer, and continues fixed dummy slots. The
regression expires the operation between selection and writing. Six focused
tests and the composed TypeScript build pass. Luna independently verified source
hashes, trace sums, denominators, slot counts and absence of late real writes.

Per the predeclared stop rule, this stage closes on the reproducible boundary
violation. No parameters were retuned or measurements rerun to obtain a pass.
There is no K1, K6 or K7 qualification or application activation. A future
boundary-budget design must explicitly account for setup/control traffic and
retain the unchanged full-scope criteria; the present study does not implement
that design.
