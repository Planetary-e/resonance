# Storage writer map for the combined-budget work

This is a source audit with bounded control writers and optional shared snapshot, journal, ciphertext and identity
reservations. Reviewed desktop selection and aggregate controls are now available
as an opt-in. The production writer/retained-root audit is complete for the
selected managed-output scope described below.
Bounds below concern encoded regular-file bytes;
they do not measure filesystem allocation, physical free space or device energy.
Use [the inventory and registry guide](v0.4-combined-storage-budget.md) for the
implemented behavior and its validation.

## Shared snapshot writer

`packages/core/src/local-encrypted-state.ts` owns encrypted snapshot creation,
replacement, temporary cleanup and per-file process locks. It encodes and checks
`maxBytes` before opening a temporary file, writes every byte, flushes the file,
renames it and flushes the directory on POSIX. Old and replacement images coexist.
Capacity refusal preserves the old snapshot; an uncertain write poisons the open
handle. With an explicitly supplied managed authority it now reserves twice its
encoded cap plus 8 KiB of lock/recovery headroom before opening, captures immutable
path/cap values and retains a lease for later writes. Reopening authenticates state and refuses missing protected components.

A combined authority must cover **initial open as well as later `write()`**.
Opening a component can create its directory, lock, initial state, or a provably
pristine subordinate slot. An HTTP apply callback alone does not cover these
writes. Metadata/lock recovery and authenticated cleanup also need an explicit
allocation. Never release a history allocation merely because a file disappeared.

the ciphertext archive limit with the much larger set of owner files.

## Desktop, operator and supervisor outputs

- `admission-operator-files.ts` writes bounded, exclusive outputs with file and
  directory flushing. Configuration, enrollment exports and reviewed limit files
  can be outside the history roots. Desktop-approved outputs now retain their
  individual paths before writing and participate in aggregate inventory; the
  CLI supports repeated `--file` selections without scanning parent folders. A
  managed authority now reserves these exact files before creation. Pre-reserved
  outputs must fit their declared directory or exact replacement scope.
  CLI-created files and input keys are not automatically added by desktop bookkeeping.
- `session.ts` atomically replaces bounded desktop settings. The durable
  `history-storage-registry.ts` retains approved history locations independently
  of that settings replacement. The inventory now includes its own manifest and bounded interrupted temporary
  files. Optional reservations now charge the 129 MiB registry peak plus 8 KiB
  ownership. A changed update refuses when 128 temporary slots are occupied.
  Settings reserve nine 64 KiB images (one current and eight temporary slots)
  plus 8 KiB ownership; old interrupted candidates stay charged and are retained.
- `relay-supervisor.ts` renders its complete native output set without side effects,
  validates one MiB per file and reserves all outputs before writing any. Plist,
  unit, PowerShell and task XML files use the atomic writer's nine-image plus 8 KiB
  ownership peak. Native commands run only after durable file publication, and
  remain mocked in tests. A separate one-use start handle verifies the published
  files after the caller releases its storage scope; preparation runs no native
  commands. The combined install convenience refuses managed scopes. OS-maintained service databases/copies are outside this
  application-managed encoded-file budget; old installed definitions are included in desktop adoption before handoff.
- The discovered unbounded macOS `relay-service.log` path is addressed for new
  service definitions by [bounded structured diagnostics](v0.4-relay-diagnostics.md):
  two 1 MiB files, with native stdout/stderr capture disabled. Startup and runtime
  errors remain available through the structured sink, and authenticated stats
  report failures/drops. Existing installed definitions and legacy log files are
  unchanged until explicitly updated. An optional captured lease now reserves both files and 8 KiB of diagnostic
  lock headroom before directory creation. Lease failure drops diagnostics without
  changing accepted protocol state. Legacy files and installed service updates
  still need adoption in the future total managed-output budget.


## Export APIs and out-of-scope application data

`publication-store.ts`, `mailbox-store.ts`, `matching-engine.ts`, `hamming-index.ts`
and `hnsw.ts` expose persistence/export methods. HNSW includes a native
`writeIndexSync` call, so searching JavaScript file-write imports alone misses it.
The current `server.ts` rebuilds live relay state from the operation journal and
does not call these export methods. The final audit found that the public methods
could nevertheless write unreserved files when called under a managed authority.
They now refuse managed state before creating a directory or invoking the native
HNSW writer. The guard retains construction-time ownership, so moving an object
outside its original scope does not restore an unbounded export capability; an
unmanaged object also cannot export inside another authority. Independent exports
remain available. A future managed exporter requires a bounded reserved format.

Validation: TypeScript and 38 tests / six files (2.98s), including all six export
entry points, standalone exports and real selected Node runtime regression.
The resulting follow-up is implemented: a selected desktop can review later
role/output locations in its existing authority. Scope approval creates no role
files, grants no additional bytes and cannot reclassify missing allocated history
as a new folder. Actual role setup still registers and validates its outputs.

The app database, one-use wallet, models, previews and unrelated user files are
not included in the current history/runtime inventory. The UI explicitly names the
scope of its budget. A relay-data quota must not be advertised as a whole-app or
whole-device quota.

## Completed selected-output audit

The final source pass covered direct file writes, append, rename, temporary cleanup,
filesystem locks and native `writeIndexSync`, across core, relay, desktop server and
operator scripts. The audit follows reachable entry points, not only helper names:

| Entry / retained location | Enforcement and evidence |
| --- | --- |
| Selected Node runtime | Selection validated before diagnostics and runtime imports; captured owner spans startup, callbacks and shutdown. Real Node publication, full-capacity refusal, pause, SIGKILL and restart preserve identity and allocations. |
| Selected history CLI | Maintenance/runtime claims precede commands and remain held through deferred volunteer-service shutdown. Real signed socket traffic, restart and complete budget exhaustion preserve existing histories. |
| Desktop control and role changes | Prepaid pause/settings controls can operate beside the live ledger owner; stopped setup/recovery/activation use the same exclusive authority. Additional locations require a bounded session-owned review. Real protected-owner setup after scope expansion preserves the original selection and limit. |
| Retained runtime/history/recovery roots | Current and previous configured roots plus the independent registry are inventoried. Missing retained roots or an allocated registry refuse adoption. Captured recovery/provisioning/readiness factories retain authority when creating later writers. |
| Exact outputs and interruptions | Configuration/enrollment exports, settings, registry, selection attempts, native definitions, diagnostics sibling, legacy log and unknown namespaced sidecars are retained. New native parents are reviewed separately; invalid prefixes remain charged rather than promoted or erased. |
| Generation / repair headroom | Fixed child paths and authenticated legacy location pins keep one allocation per component. Child and next-slot peaks precede parent activation; manifests, ciphertext and recovery copies have separate replacement peaks. Full-budget process-death tests preserve accepted work and pending reservations. |
| Public materialized exports | Refuse managed ownership before mkdir/write/native export, including after construction scope exits; live runtime uses the reserved journal. |
| Independent authority/issuer scripts | Refuse an explicitly selected relay budget. Their keys, permit ledgers and output files remain separate until an output is explicitly adopted; selected relay accounting does not supervise independent processes. |

Storage authority metadata pays its own fixed control reservation. Runtime and
standalone locks, maintenance markers, desktop settings/registry, bootstrap intent
and attempt fences have explicit bounds and replacement headroom. Committed
allocations and adopted byte floors are monotone; file disappearance and failed
operations never free allowance. New work refuses capacity before output, while
already allocated components retain their funded repair/control space.

Validation for the completed scope: TypeScript and **440 tests / 36 files in
190.80 seconds**, with **563 source/configuration hashes unchanged** during the
run. The group includes core adoption/reservation invariants, direct/control
writers, native-file preparation, actual selected runtime and CLI, desktop
bootstrap/adoption/publication/activation, role changes, protected recovery and
process-death tests. A focused 85-test group overlaps this result. Interactive
localhost verification also completed setup, limit edit and location cancel/apply
with temporary account data. Native OS commands and model initialization were
mocked for that UI check; real selected Node behavior has separate coverage.

This closes the combined managed-output storage row. It does not establish an
OS-enforced quota, physical filesystem/free-space bound, whole-app/device budget,
anti-rollback hardware, protection from independent local writers, future role
capacity, real OS supervision or network/admission readiness. Quorum-safe history
compaction and complete policy/witness recovery remain separate roadmap work.

See [scope review and validation](v0.4-combined-storage-budget.md#later-role-locations-and-completed-storage-audit).
