# Model cache memory and application evidence

## Cause and correction

The installed Transformers.js 4.3.0 filesystem `FileResponse` immediately creates
a Node read stream and forwards every chunk into an unconsumed web stream.
Its ONNX loader then returns the filename to native ONNX Runtime without reading
or cancelling that body. Each cached 547,552,426-byte model load therefore also
reads the entire model into JavaScript buffers. Disposing the native session does
not stop that separate read. This was confirmed in the installed source/bundle
and by counting 1,642,657,278 redundant bytes across three model lifetimes.

The application's memory spike appeared during credential import because the
earlier background reads completed then. It was not evidence that the credential
format or RSA operation needed a gigabyte.

`model-file-cache.ts` uses Transformers.js's documented
[custom cache hook](https://huggingface.co/docs/transformers.js/api/env).
For the standard Hugging Face repository layout and filesystem cache, it returns
cached ONNX filenames directly. Small metadata reads are bounded at 16 MiB;
downloaded weight files at 2 GiB. Downloads stream into an exclusive temporary
file, honor write completion, check size, flush and atomically replace the final
file. Failure removes only that temporary file and retains an existing model.
Invalid keys, traversal, oversized files and partial downloads are rejected.
Explicit custom caches and nonstandard repository layouts are left to their
configured implementation; these measurements do not cover them.

No model, dtype, projection, tokenizer, prefix or matching threshold changed.
The evaluation runner also now disposes both its bootstrap probe and its shared
engine, including failure paths.

## Evidence

- [Runtime settings comparison](../evals/embedding-resources-2026-10-18.md): two
  CPU threads and disabling the CPU arena failed their predeclared adoption gates.
  Production runtime settings stay unchanged.
- [Cache comparison](../evals/model-cache-comparison-2026-10-18.json): two isolated
  trials per variant in reversed orders, with a one-second I/O settling interval
  per model lifetime. Median peak RSS falls from 1,481.7 to 988.2 MiB (33.3%).
  Corpus inference changes from 2,598 to 2,473 ms; lifecycle CPU from 15.192 to
  13.826 seconds. All 200 vectors and pilot fingerprints are byte-identical in
  every trial. Redundant model stream bytes fall from 1,642,657,278 to zero. All
  predeclared gates pass. Even-sized samples use the arithmetic midpoint median.
- Actual two-process application, [before](../evals/v04-app-memory-before-2026-10-18.json)
  and [after](../evals/v04-app-memory-cache-2026-10-18.json): all five checks pass,
  including publish, search, match delivery and deduplication across lock/unlock.
  Peak RSS changes from 2,012/1,485 to 1,080/1,098 MiB. After credential import,
  array buffers drop from about 1,051 to 14 MiB. Recorded bytes are WebSocket
  payloads, not total TCP/TLS traffic.
- [Cold-cache exercise](../evals/model-cache-download-2026-10-18.json): the real
  library downloads 548,267,042 bytes of model artifacts through a local streaming
  fetch fixture, closes every stream, then reloads with downloads disabled and
  produces a byte-identical embedding. This tests library integration, not a live
  Internet download. The temporary cache is removed afterward.
- [Protected application repeat](../evals/v04-protected-app-cache-2026-10-18.json):
  all nine checkpoints pass with five observers, five witnesses, one coordinator,
  55 histories and all six paired searches. Six owners reopen; witness and
  observer quorum-loss behavior remains correct. Application peaks are
  1,050.5/1,070.4 MiB. Duration is 154.638 seconds including rate-window cooldowns;
  WebSocket payloads total 11,033,645 bytes, measured CPU 29.778 seconds. This is
  still local process evidence, not Internet or device-energy certification.
- Forty-four focused tests in four files pass, including the real cached model,
  session lifetime, atomic replacement, oversize, interruption and unsafe cache
  requests. Repository and standalone evaluator TypeScript checks pass. Pure
  cache tests join the existing three-OS desktop CI matrix.

Reproduce from the repository root:

```sh
npm run eval:embedding-resources -- --cache-comparison --enforce --out /tmp/model-cache.json
node --import tsx scripts/eval-model-cache-download.ts --out /tmp/model-download.json
npm run eval:v04-real-app -- --out /tmp/app-memory.json
npm run eval:v04-real-app -- --protected-admission --concurrent-searches --out /tmp/protected-app-memory.json
```

The original short runtime comparison exited while redundant I/O could still be
pending. Its approximately 1 GiB peaks were not a steady-state guarantee. The new
settling intervals and application measurements make that limitation explicit.

This correction does not establish a universal memory ceiling. Long text,
simultaneous inference, prolonged use and supported Windows/Linux device budgets
still need bounds and measurement. CPU seconds do not measure device energy.
