## 4. Canonical binary protocol records

All records use big-endian integers, fixed field order, exact lengths, unique signers, and no trailing bytes. A digest is 32 B, an Ed25519 public key/signer is 32 B, and an Ed25519 signature is 64 B. `H=256` is the authenticated archive header. Identical identity and bytes replay idempotently; identical identity with different bytes is a conflict. A valid prefix never makes a partial record available.

### 4.1 Transition, mutation, votes, and certificates

`T` remains a 28-byte version/view/sequence header plus sixteen 32-byte digests:

```text
T = 28 + 16*32 = 540 B
```

The ordered digests bind configuration, previous transition, previous stable cut, previous state, original command, next state, semantic mutation, complete evidence, index, policy, activation history, observer state, delegation, terminal/old-cohort fence, funding/layout, and genesis/context trust root.

The finite-scenario mutation placeholder remains:

```text
M = 2,048 semantic bytes + 5*32 reference bytes = 2,208 B
```

This is **not an original-command bound**. Section 8 rejects the design partly because this and the state/index limits do not implement the inherited reducer capacities.

One generic vote now carries every scope field needed for authentication:

```text
V = magic[8] + version[4] + phase[1] + signer[32] + signature[64]
  + configuration[32] + genesis[32] + sequence[8] + view[4]
  + transitionDigest[32] + stableStatementDigest[32]
  = 249 B
```

PREPARE and COMMIT use the zero stable-statement digest. STABLE uses `digest(K)`. A four-signer certificate is self-contained:

```text
Q = magic[8] + version[4] + phase[1] + configuration[32] + genesis[32]
  + sequence[8] + view[4] + transitionDigest[32]
  + stableStatementDigest[32] + count[2] + 4*(signer[32]+signature[64])
  = 539 B
```

A QC is valid only for four distinct members of the configuration authorized at that exact historical sequence. A union of old/new/historical signers is invalid.

### 4.2 Canonical stable statement, suffix, and head

`K` is the single canonical stable statement. Its twelve ordered digests are configuration, genesis, transition, next state, complete evidence, index, delegation, complete storage layout, snapshot manifest, previous stable statement, terminal/old-cohort fence, and funding/layout:

```text
K = magic[8] + version[4] + sequence[8] + view[4] + 12*32 = 408 B
```

For a non-cut transition, the snapshot-manifest digest names the existing immutable generation and the storage digest names the complete suffix. For a cut, it names the pending manifest only after every page, the manifest, index, and delegation floor have four durable copies. Thus a STABLE vote cannot authenticate a transition while leaving storage, evidence, delegation, or snapshot identity ambiguous.

```text
Y = H + T + prepareQ[539] + commitQ[539] + mutationLength[4] + M
  = 256 + 540 + 539 + 539 + 4 + 2,208
  = 4,086 B

Z = H + K + stableQ[539]
  = 256 + 408 + 539
  = 1,203 B
```

The committed chain is the unique digest-linked sequence of `Y` records beginning at `Z.previousStable` and advancing by exactly one global sequence per entry. Each entry carries both QCs and its exact certified mutation. A gap, parent mismatch, same-sequence different digest, wrong cohort, or invalid QC stops selection.

The finite index locator remains `Index=H+72*197=14,440 B`. A 197-byte entry contains six 32-byte scope/proof/frame/binding/issuer-or-configuration/spend-or-activation identities, kind[1], flags[1], version[1], and two zero reserved bytes. Indexes are locators only; original evidence remains authoritative. The 72-entry limit is explicitly only a finite-scenario assumption.

### 4.3 Prepared locks and exact NEW_VIEW contents

A durable prepared lock is:

```text
Lock = sequence[8] + preparedView[4] + transitionDigest[32]
     + prepareQ[539] + pendingRecordDigest[32] + flags[1]
     = 616 B
```

`pendingRecordDigest` names the durable original command, `T`, and `M`; the lock is not usable without that exact pending record. Locks survive view changes and are never treated as orphans.

Each VIEW_CHANGE record contains four lock slots and four suffix digests, including empty slots with canonical zero values:

```text
VC = magic[8] + version[4] + signer[32] + configuration[32] + genesis[32]
   + oldView[4] + newView[4]
   + stableHeadDigest[32] + stableStatementDigest[32]
   + committedFloorSequence[8] + committedFloorTransition[32]
   + suffixStart[8] + suffixCount[1] + 4*transitionDigest[32]
   + lockCount[1] + 4*Lock[616]
   + stateRoot[32] + evidenceRoot[32] + delegationRoot[32]
   + indexRoot[32] + storageRoot[32] + snapshotRoot[32]
   + signature[64]
   = 3,078 B
```

The exact durable NEW_VIEW record is:

```text
NV = H + magic[8] + version[4] + configuration[32] + genesis[32]
   + newView[4] + baseSequence[8]
   + 4*VC[3,078] + selectedNextLock[616]
   + 4*Y[4,086] + newViewQ[539] + selectedStableZ[1,203]
   + localFenceDigest[32] + leaderSignature[64]
   = 31,454 B
```

Empty suffix slots contain canonical zero-filled records of the same reserved length and are never executed. `NV` therefore authenticates the four VIEW_CHANGE records, every reported prepared lock, the selected lock, the selected stable statement/head, and the complete available committed suffix/QC chain. Referenced pending `T/M` records must also have four exact copies before their locked value can be reproposed. `NV` is installed locally and at four replicas, with file and directory fsync, before any proposal in the new view. A lower local view, stable sequence, committed floor, or prepared `(sequence,view)` fences stale installation.

## 5. Transition, view selection, acknowledgment, and retirement

### 5.1 Command order

1. Admission authenticates the original command, policy cutoff/freshness, configuration, previous transition, old-cohort fence, competing-writer lease, suffix capacity, and all physical/work/network reservations.
2. The leader evaluates the original reducer once and constructs `T/M`. Every voting member, including the leader, independently evaluates the same command once against complete relevant evidence and requires byte-identical `T/M` and roots.
3. Each member appends new original evidence, fsyncs it, obtains four exact evidence acknowledgments, then durably writes the pending command/`T/M` and obtains four matching acknowledgments. Only then does it emit PREPARE.
4. Four PREPARE votes form `prepareQ`. Before COMMIT, each member verifies it, matches its pending record, durably installs `Lock`, and obtains four matching lock acknowledgments.
5. Four COMMIT votes form `commitQ`. Each member appends `Y`, advances its committed floor, fsyncs, and obtains four exact suffix/floor acknowledgments. Execute applies `M` and index changes without rerunning the reducer.
6. After the executed roots are computable and the durable suffix floor exists, each member signs STABLE over `K`. At a cut, all pending pages/manifest/index/delegation records must already have four copies before that vote.
7. Four STABLE votes form `stableQ`. `Z` is locally installed and acknowledged by four replicas before client acknowledgment, completion notification, old-cohort freeze, readiness export, or successor funding receipt.

At most four suffix entries exist. A fifth command refuses until a cut completes. An atomic replacement includes temporary-file fsync, atomic rename, and parent-directory fsync. A replica acknowledgment before its own durable barrier is invalid. A crash after execute but before the stable barrier leaves an uncertain outcome, never a second accepted outcome.

### 5.2 Deterministic NEW_VIEW selection

The new leader performs these steps deterministically over the union of its local durable state and four distinct valid `VC` records, sorted by signer for tie-independent processing:

1. Require one configuration/genesis/new-view identity and a view higher than every installed local view. Verify every original signature against the cohort authorized at the reported historical sequences.
2. Select the greatest committed sequence having a continuous `Y`/commit-QC chain from a valid stable head. Equal sequence with a different digest is a conflict and refuses the view; it is not resolved by arrival order or a majority of payloads.
3. A local stable or committed floor higher than the selected remote floor must be imported and verified before installation. A lower `NV` cannot truncate it. A missing predecessor, skipped sequence, wrong configuration, or incompatible same-sequence cut refuses installation.
4. For each unlocked sequence after the committed floor, select the lock with greatest `(preparedView,sequence)` and then transition digest only as a canonical ordering key. Equal `(sequence,view)` with different values refuses. Committed entries take precedence over locks for the same sequence.
5. Every surviving lock remains in `NV`; `selectedNextLock` is the lowest unlocked global sequence's selected value. A different value at that sequence is forbidden. An unlocked empty sequence is permitted only when neither the four records nor local durable state contains a lock/pending value for it.
6. Resolve locked sequences in global order before admitting a new command. Fetch the exact pending records by digest and prove four copies. No reducer rerun occurs.
7. Persist the exact `NV` and local fence before signing or accepting a proposal in that view.

This rule deliberately favors bounded refusal over liveness when locks or ancestry are ambiguous. Four-of-five intersection prevents two conflicting valid four-signer certificates under at most one Byzantine signer; equivocation evidence is still retained.

### 5.3 Promotion, retirement, retry, and old-cohort fence

For a non-cut stable head, promotion updates only `Z`; suffix entries remain. For a cut, the pending generation becomes selectable only through an atomic local pointer naming the new `Z` and manifest after four complete copies exist. Recovery selects either the old complete head/generation plus suffix or the new complete generation, never a mixed generation.

Covered suffix entries and superseded mutable pages may retire only after the new `Z`, all referenced pages/manifest/index, and delegation floor have four durable copies and local installation. Original immutable evidence, permanent denials, conflicting votes, alternative certificates, required historical delegations, and unresolved prepared locks never retire as suffix garbage.

An exact retry first resolves the existing certified outcome and emits no duplicate notification. The same request identity with different bytes, parent, action, or binding is a conflict. Orphan evidence has no business effect but consumes declared `C` and all attempted work.

A configuration transition becomes effective at its stable terminal cut only after successor reservations and activation are funded. Before that stable barrier, old-cohort votes needed to validate the terminal transition remain valid. Afterwards, every old-cohort proposal, vote, checkpoint, delegation, and write is rejected regardless of view. The successor inherits terminal sequence `s` and proposes next at `s+1`; global history never resets. Old members retain required private evidence/delegations until four successor copies and local installation exist, but cannot authorize new business after the fence.

## 7. Immutable chunked snapshots and complete failed extents

The finite state placeholder is `J=65,536 B`. It is divided into sixteen immutable 4,096 B plaintext pages. Each sealed page and its manifest are:

```text
Page       = H + AEAD[28] + 4,096 = 4,380 B
Manifest(n)= H + magic[8] + version[4] + generation[8] + sequence[8]
             + snapshotDigest[32] + pageCount[2] + n*(pageDigest[32]+offset[4]+length[4])
           = 318 + 40*n B
Manifest(16) = 958 B
```

Pages are content-addressed and copy-on-write. Unchanged pages are shared by digest; preflight nevertheless reserves the complete current+pending maxima. New pages are written and fsynced before the manifest; the manifest is fsynced before the stable head; the local pointer changes last. A torn pending page or manifest never damages the surviving generation. Recovery retains the complete failed page and manifest before fetching replacements. Cleanup processes one immutable extent at a time and refuses before modifying the survivor if retention is unfunded.

```text
maximum finite failed extent = Page + Manifest(16)
                             = 4,380 + 958 = 5,338 B
F headroom                   = 32,768 - 5,338 = 27,430 B
```

This resolves the finite maximum snapshot tear without enlarging `F` or discarding the failed extent. Section 8 shows why this does not establish original-state physical closure.

### 8.2 Why the original contract cannot fit

The inspected original reducer does not enforce 72 semantic rows or a 65,536 B canonical state. `parseWitnessInheritedEvidence()` permits up to 10,000 combined votes/certificates/accepted rows/denials, plus up to 10,000 sets and 10,000 activations. `witnessConstraint()` requires every accepted row and denial for correct `fresh/bound/split/conflict/denied` results. More than 64 authenticated configurations and all original evidence must remain available; none can be truncated to a latest winner.

Even one minimal binary accepted row needs at least:

```text
owner[32] + issuerPresence[1] + spend[32] + actionLength[2]
+ emptyAction[0] + bindingReference[32] + rowTag[1] = 100 B
10,000 * 100 = 1,000,000 B
```

This is a generous lower bound: non-null issuer keys, nonempty actions, denials, competing bindings, votes, certificates, sets, activations, policy/observer state, and configuration ancestry add more. Current+pending plaintext alone would require 2,000,000 B, exceeding `D` by 1,475,712 B before any other record.

Using the same full-page prospective reservation formula, 1,000,000 B needs 245 pages and `Manifest(245)=10,118 B`:

```text
two page generations       2*245*4,380 = 2,146,200
two manifests                2*10,118 =    20,236
other finite D obligations                  136,428
                                           ---------
accepted-row-only D reservation             2,302,864 B
D excess                       2,302,864-524,288 = 1,778,576 B
```

Externalizing rows to immutable evidence does not fix this: original evidence is retained in `C`, whose finite forecast already has only 3,549 B headroom, and indexes cannot replace evidence or semantic rows. A 2,208 B mutation and 16,384 B command are likewise not proven maxima for all original commands. A refusal at 72 proofs/2,208 B mutations/65,536 B state would be a new reduced contract, not the accepted original contract.

**This is the decisive rejection.** There is no original-cap physical forecast or exact original-lifetime cumulative maximum to certify. All fitting work totals below describe only the finite scenario and cannot override this counterexample.
