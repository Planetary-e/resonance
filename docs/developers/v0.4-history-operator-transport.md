# Operator recovery over outbound relay links

Status: opt-in command transport, 2026-10-17. The reviewed history commands can
use the same authenticated relay links as the runtime, including a volunteer
bridge when both the owner and history volunteers are outbound-only. The operator
process opens no listener and advertises no publication, mailbox, query or
replica capacity. The five history members and four-copy requirements stay fixed.

## Explicit configuration

Set `RESONANCE_HISTORY_OPERATOR_TRANSPORT_FILE` when invoking
`scripts/admission-history.ts`. Without this setting, the existing direct history
transport remains selected. An invalid configured file is an error; a missing
connection or wrong identity cannot fall back to the direct member endpoints.

```json
{
  "version": 1,
  "identityDirectory": "retained-controller-identity",
  "identityPassphraseFile": "controller-passphrase.txt",
  "expectedRelayId": "<independently retained infrastructure DID>",
  "linksFile": "owner-links.json",
  "contacts": [],
  "deadlineMs": 120000
}
```

All fields are required. File paths resolve relative to this configuration file.
It is a bounded 64 KiB regular JSON file; paths and deadlines are bounded and
unknown fields are refused. A request already cancelled cannot start a session. `deadlineMs` bounds the transport session from its
first network operation, between 100 and 300,000 ms. Individual exchanges keep
their existing, shorter protocol deadlines. Reopening a command creates a new
session; it does not erase pending work or authorize a new recovery view.

`linksFile` is the existing [owner routing file](v0.4-history-owner-runtime.md):

- Version 2: `contacts` must be empty. The one bridge identity and endpoint come
  from the independently reviewed routing file.
- Version 1: supply exactly five distinct `{ "relayId": "...", "endpoint": "..." }`
  contacts matching its five infrastructure identities. Each must be reachable
  by an outbound connection. The operator has no inbound listener. Five entirely
  outbound-only members therefore need version 2 and a reachable bridge.

Only WSS or explicitly permitted loopback WS endpoints are accepted. Connection
establishment verifies the remote infrastructure identity and its signed binding
to the contacted endpoint. History responses still require their original member
signatures; a bridge never becomes a vote or a retained history copy.

## Retain the infrastructure identity

The identity directory must already contain `relay-identity.json` in the encrypted
infrastructure-keystore format. The passphrase file follows the
[desktop secret-file rules](v0.4-history-desktop-service.md). The command reads the
keystore without generating, migrating or rewriting it, and compares its DID to
`expectedRelayId` before opening any connection. Missing, corrupt, plaintext,
wrong-passphrase or mismatched identity files fail closed. Reading is bounded even
if the file grows; a named pipe cannot block the identity open.

Back up this identity and its passphrase independently of a disposable owner or
recovery working directory. Enroll its DID as an allowed controller at the members
or as a controller in each bridge route before recovery is needed. A separately
retained operator identity may be authorized alongside the runtime identity.

If reusing the runtime's retained infrastructure identity, stop that runtime first.
Two active instances with the same DID can block each other's authenticated
connection. This transport does not provide a distributed identity lease or stop
an independently running desktop service. A completed local service stop does not
prove that the bridge has observed its disconnect; an old connection must close
or expire before the same identity can reconnect. The desktop now provides a
[persistent pause and local process exclusion](v0.4-desktop-history-maintenance.md);
guided recovery and activation remain open. Likewise, do not
open the same writable owner/recovery directory in competing processes.

## Command behavior

The same configuration applies to `owner-ready`, `owner-inspect`, recovery
plan/start/step/restore and approved protected maintenance. Checkpoint, agreement,
selected-history transfer and generation provisioning all use the selected router.
The direct endpoint strings retained in the owner configuration remain required
protocol metadata; they are not dialed in this mode.

Adapters are lazy: owner export/preparation, maintenance review, recovery status
and restore review do not open sockets or read the infrastructure passphrase/key.
Their existing local validation and explicit approval rules remain in force.
Recovery planning does perform bounded network discovery; it is not an offline
command. A session starts only when its first protocol exchange is requested.

Closing, SIGINT, SIGTERM or the session deadline cancels connection waiting and
unfinished handshakes, closes active links and clears mutable infrastructure key
bytes. Active links send a WebSocket close and allow at most one additional second
for its acknowledgement before forced local teardown. It does not undo a request that may already have reached a volunteer.
The durable pending intent, actual agreement selection and reviewed approval
workflow continue to control retries. No mutation is transparently replayed by
transport reconnection. Passphrases represented as JavaScript strings cannot be
guaranteed erased from memory.

## Validation boundary

Package compilation, strict standalone command-script typechecking and **60 tests
across ten files** passed locally in **119.65 seconds**, including the existing
five-volunteer churn scenario. Complete CI at `b11941d` subsequently passed
**171 files / 1,076 tests in 1444.47 seconds**, plus **44/44** quick metrics:
[run 38989944382](https://github.com/Planetary-e/resonance/actions/runs/38989944382).
That result predates desktop maintenance and separate policy-bound history
locations. The SIGTERM and named-pipe negative tests run on POSIX hosts.

The integration scenario uses real CLI subprocesses, a bridge and five local
outbound-only volunteers. It retains a real token binding, removes the owner
working directory, performs reviewed recovery and restores admission in a new
directory. All four history protocols cross the bridge; direct history endpoints
are deliberately unreachable. Negative checks cover strict contacts, lazy offline
adapters, missing/encrypted identity handling, a silent connection deadline and
absence of direct fallback. Existing direct command flows remain covered.

This is local process/network evidence, not independent volunteer availability,
Internet reachability, a desktop recovery UI or native OS key-storage validation.
