# A volunteer bridge for outbound-only history participants

Status: opt-in Node runtime, 2026-10-17. A reachable volunteer can carry history
requests between a protected owner and enrolled members that only open outbound
connections. The bridge holds no history copy and contributes no quorum vote.
Four of the original five enrolled members must still acknowledge every new
protected mutation. Existing owner/member signatures are verified end to end.

## Topology and configuration

Both sides connect to the bridge's advertised relay endpoint. Only the bridge
needs an externally reachable endpoint. This does not traverse arbitrary NATs:
the operator must supply that reachable volunteer, with WSS for public Internet
connections. Loopback WS is permitted for local tests. No managed or continuously
available service is assumed.

Keep the owner's prepared history configuration and independently retained five
member keys. Set `RELAY_ADMISSION_HISTORY_LINKS_FILE` to a regular JSON file, at
most 64 KiB, with the following version-2 shape:

```json
{
  "version": 2,
  "members": [
    { "publicKey": "member-1-history-key", "relayId": "member-1-relay-DID" },
    { "publicKey": "member-2-history-key", "relayId": "member-2-relay-DID" },
    { "publicKey": "member-3-history-key", "relayId": "member-3-relay-DID" },
    { "publicKey": "member-4-history-key", "relayId": "member-4-relay-DID" },
    { "publicKey": "member-5-history-key", "relayId": "member-5-relay-DID" }
  ],
  "bridge": { "relayId": "bridge-relay-DID", "endpoint": "wss://bridge.example/" }
}
```

Replace every placeholder with independently selected actual values. Members
must match the existing history context; their keys and infrastructure identities
are distinct, and the bridge identity differs from all five targets. The bridge
contact is pinned before discovery. A conflicting controller pin is refused.
Direct member endpoints are never used as fallback. Version 1 continues to select
direct authenticated relay links.

Each enrolled volunteer uses its existing
[runtime configuration](v0.4-history-volunteer-runtime.md), with the bridge's
identity and endpoint in `controllers`. That authorizes the transport identity;
it does not give the bridge the owner's signing authority. The owner and members
may leave `RELAY_PUBLIC_ENDPOINTS` empty.

On the bridge, set `RELAY_HISTORY_BRIDGE_FILE` to a regular JSON file of at most
64 KiB. It contains exactly `version: 1` and a `routes` array:

```json
{
  "version": 1,
  "routes": [
    { "controllerRelayId": "owner-relay-DID", "targetRelayId": "member-1-relay-DID" },
    { "controllerRelayId": "owner-relay-DID", "targetRelayId": "member-2-relay-DID" },
    { "controllerRelayId": "owner-relay-DID", "targetRelayId": "member-3-relay-DID" },
    { "controllerRelayId": "owner-relay-DID", "targetRelayId": "member-4-relay-DID" },
    { "controllerRelayId": "owner-relay-DID", "targetRelayId": "member-5-relay-DID" }
  ]
}
```

There must be 1–32 distinct controller/target pairs and at most 32 identities.
Self-routes, unknown fields and arbitrary destination URLs are refused. Configure
the bridge's ordinary data directory, retained infrastructure identity and public
relay endpoint separately. This file never enrolls or initializes history.

An authenticated controller can forward only to its explicit targets. Targets
cannot use their transport authorization to act as controllers. The forwarding
wrapper accepts only checkpoint, agreement, transfer and provision; nested
bridging is refused. Original signed frames and action-specific size limits are
preserved. Recovery callers use the same router's four transports.

## Concurrency, cancellation and resource controls

One missing member must not hold all five requests behind a serial socket queue.
The owner's bridge socket permits four outgoing streams; a fifth waits within its
original deadline. The bridge permits four live incoming streams **across all
controllers**, with at most four per controller socket. Target sockets retain
the ordinary one-stream limit. All roles still share eight charged operations
and 64 MiB of reserved buffers per router.

Each forwarded RPC is charged for incoming and outgoing work. Forwarding may wait
for an outgoing credit only while already charged as incoming work. Cancellation
releases its live ingress quota but retains its global operation charge until the
handler settles. This prevents cancelled handlers evading the cap while allowing
their cleanup to finish before the next quorum attempt. Queues are bounded;
connection, queue and transfer waits cannot renew the maximum 30-second owner RPC
deadline. Cancellation propagates downstream, including when the router detaches
from a still-open shared socket. Lost transport never silently resends a mutation.

The existing resource policy can refuse new forwarding work. Socket accounting
includes actual chunk/acknowledgement traffic; new-work admission charges logical
request bytes. Buffer reservations are not peak process memory or a hard CPU,
bandwidth or energy limit. A bridge can also host an independently enrolled role,
but only that role's authenticated durable receipt can count as a history copy.

## Availability, observation and evidence

The configured bridge is an availability dependency. Its disappearance interrupts
transport without changing the original history or quorum. After reconnection,
the durable protocol can explicitly retry the same pending mutation. This version
does not automatically select another bridge or change transport/member pins.

The bridge observes infrastructure identities, target routing, signed protocol
metadata, sizes, timing and encrypted history. It can delay/drop traffic. It does
not provide user anonymity or conceal infrastructure activity; retained payload
encryption and signed history validation continue to serve their existing roles.

Local real-socket tests keep the first member disconnected while the other four
complete writes, reject three-copy progress, reconnect the fourth and recover a
lost owner's complete history through the bridge. Real Node owner/bridge process
tests keep admission closed until four members connect, restart the bridge and
owner, and preserve accepted real-token bindings and double-spend rejection.
Negative tests cover unauthorized routes, nested forwarding, oversized frames,
resource refusal and cancellation with handlers that finish late.

Desktop configuration/health and independent Internet, volunteer-overlap and
energy validation remain separate roadmap work. These local tests do not certify
independent operators, arbitrary NAT traversal or a continuously available quorum.
