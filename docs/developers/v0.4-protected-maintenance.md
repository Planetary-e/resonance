# Protected admission maintenance

Status: explicit operator commands, 2026-10-17. Stop the owner's relay before
maintenance; the existing writer lock refuses concurrent access. These commands
open an existing protected v3/v4 ledger. They never initialize a missing ledger,
promote a local-only history or select replacement volunteers.

Use the owner configuration, encryption key and authenticated policy from the
[operation guide](v0.4-volunteer-history-operations.md). The supplied policy must
equal the policy retained with the spend image. Apply a valid successor policy
through the explicit `owner-ready` command before reviewing maintenance under it.
The old local-only maintenance scripts keep their protected-format refusal.

## Retire a key after its final retry cutoff

```sh
node --import tsx scripts/admission-history.ts owner-retirement-plan owner-config.json policy.json owner-storage.hex owner-directory <issuer-key-fingerprint>
node --import tsx scripts/admission-history.ts owner-retire --approve <digest> owner-config.json policy.json owner-storage.hex owner-directory <issuer-key-fingerprint>
```

The plan checks the authenticated policy, rejects its active key, requires the
final retry cutoff and reports how many attributed records will be removed.
Unattributed legacy rows remain. A permanent issuer-key denial replaces those
records in the live image; a clock rollback cannot reactivate them. Review prints
an approval digest bound to the policy, destination, key and complete retained
spend/denial state. It sends no network requests and reports `readiness: unverified`.

The mutation verifies that exact local approval before contacting volunteers,
obtains fresh readiness, then checks the plan again and commits the retirement
through the protected ledger. Success reports `readiness: confirmed` only after
four durable copies and local application. Other histories, wallets and issuance
allowances require their own independent maintenance.

## Recover proven legacy rows

```sh
node --import tsx scripts/admission-history.ts owner-legacy-plan owner-config.json policy.json owner-storage.hex owner-directory proofs.json
node --import tsx scripts/admission-history.ts owner-legacy-recover --approve <digest> owner-config.json policy.json owner-storage.hex owner-directory proofs.json
```

The file uses the [existing legacy-proof format](v0.4-legacy-spend-recovery.md):
1–32 original capability proofs, at most 64 KiB, binding the original token, issuer
key, action and request. Verification must reproduce an existing unattributed row
exactly. The issuer must be inactive and past its final retry cutoff. Changed,
absent, duplicate or invalid proofs refuse the entire batch. Malformed JSON errors
do not echo the private file contents.

Review is offline and exposes only counts, key fingerprints and the approval
digest. Applying it requires the same fresh four-copy boundary as retirement.
The mutation removes the proven rows and rows already attributed to those keys,
preserves unproven legacy rows and current-key records, and retains permanent
denials. Additional proof batches may later remove remaining rows under an
already retired key. Only verified attributions and fences are replicated; raw
bearer proofs stay local. This trusts the owner to perform proof verification,
as specified by the existing protected record format.

## Incomplete attempts and limits

If only three copies answer readiness, no new maintenance mutation is accepted.
If replies are lost after the mutation was written, the exact pending ciphertext
remains. A new plan refuses incomplete state rather than issuing an approval for
a guessed result. Preserve the directory and resume explicitly:

```sh
node --import tsx scripts/admission-history.ts owner-ready owner-config.json policy.json owner-storage.hex owner-directory
```

This finishes exact pending work and requires fresh readiness. Afterward, inspect
the state or review the remaining batch again. An already completed retirement is
reported as already retired; its old approval cannot authorize another mutation.
Do not delete a pending writer or reinitialize history to retry a command.

These commands reduce the **live spend image**. They append durable retirement or
attribution records and retain old encrypted ancestors; they do not reduce the
entire archive or free policy-archive slots. A full history can still refuse new
work, including maintenance that needs another block. Quorum-safe compaction and
complete witness-history recovery remain separate roadmap requirements.

## Evidence

CLI tests run real blind-token verification and five volunteer sockets. They
verify offline review/no transmission, output privacy, stale approval, a supplied
newer policy, missing/local-only state, malformed/oversized proofs, active-key
refusal, three-copy refusal, lost mutation replies and explicit completion.
Recovered legacy evidence retains its denial through a subsequent lost-owner
recovery, and another batch works on that continuation. The five-process operator
scenario also performs CLI retirement and preserves the denial through three
lost-owner generations. Existing protected API tests cover failed flushes and
process interruption at the underlying mutation boundary.
