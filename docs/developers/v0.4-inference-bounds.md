# Bounded personal matching work

The cached model now avoids redundant file reads, but unrestricted text length
and overlapping native inference could still multiply memory and CPU use.
Personal matching therefore applies the following admission bounds before
model inference or any publication/search side effect:

- At most 8 KiB of nonempty original UTF-8 text. Rewriting cannot bypass this
  bound. Invalid input is refused before tokenization.
- At most 512 tokens, including the matching prefix and special tokens, and no
  more than the tokenizer's own smaller limit. Tokenization checks the complete
  text without truncation. Excess text is rejected with a request to shorten or
  split the description; it is never silently clipped into a different meaning.
- One native inference at a time and at most eight accepted operations in total.
  The remaining seven wait in FIFO order. A ninth request is refused immediately.
- Each operation has a ten-second monotonic allowance including queue waiting.
  Expired/cancelled queued work never starts. An already-running native call keeps
  its slot until it actually settles, even after its caller has been cancelled.

Closing the model rejects queued work and waits for the native call before
disposing its session. Desktop publication, search and held-search requests pass
the HTTP lifetime signal through inference and check it again before storing or
sending anything. Search also checks that the original session remains current.
A disconnect, session lock or expired request cannot turn a late embedding into
a new publication or network search. This does not cancel already accepted
network work or discard its durable outcome.

Invalid/excessive descriptions return HTTP 400; capacity refusals retain the
existing temporary-failure response. Accepted text uses the same FP32 model,
tokenizer, prefix, pooling, normalization and fingerprints. Existing retained
publications and held records keep their original fingerprints and release paths.
CLI search/publication validate text before loading and release the model before
relay I/O; publication also disconnects its client on failure.

## Measurements and tests

The [input budget experiment](../evals/embedding-input-budget-2026-10-18.json)
declared candidate lengths 128/256/512, a 1.5 GiB process peak, one second elapsed
and five CPU seconds per inference before running. Three real FP32 inferences per
length, in isolated processes, selected 512 tokens: worst observed time 283 ms,
CPU 1.401 seconds and peak 995.4 MiB on this machine.

The [production-engine queue exercise](../evals/embedding-queue-2026-10-18.json)
submits nine 512-token requests together. Eight finish in 2.237 seconds with
identical vectors and the ninth is refused before inference. Peak RSS is
1,020.7 MiB and the batch uses 11.141 CPU seconds. A second batch closed during
inference completes its one running call and refuses the seven queued calls.
This is dimension/capacity evidence using repeated public words, not a language
quality benchmark or universal memory guarantee.

Thirty-seven tests across core bounds, model lifecycle, real embeddings and the
desktop outbox pass. Six CLI tests cover cleanup before relay failures and after
initialization/inference failures. HTTP regressions cover all four publication /
search send / hold variants during disconnect and a session lock during search.
Tests also cover queue overflow, deadline consumption, delayed timer callbacks,
native draining, byte/token overflow, a smaller model limit and input rejection
before side effects. The new lightweight cases join the three-OS CI matrix.

The [actual application repeat](../evals/v04-app-bounded-inference-2026-10-18.json)
passes all five publication/search/mailbox/deduplication checks in two Node
processes with the new engine. Peaks are 1,092.1/1,097.7 MiB; duration 27.483
seconds, payload bytes 568,280 and CPU 14.683 seconds. This repeat uses the base
local admission fixture; the preceding protected 55-history run is separately
recorded in the model-memory report.

Reproduce from the repository root:

```sh
node --import tsx scripts/eval-embedding-input-budget.ts --out /tmp/input-budget.json
node --import tsx scripts/eval-embedding-queue.ts --out /tmp/embedding-queue.json
```

Native inference cannot currently be forcibly interrupted. These bounds prevent
additional work from starting while it drains; they do not create an OS memory
quota or an energy measurement. Supported-device measurements, sustained use and
overall application/relay resource accounting remain separate requirements.
