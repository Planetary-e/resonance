## Actual v2 output export (opt-in evaluation artifacts)

`packages/eval/src/fingerprint-actual-export.ts` exports `captureEvaluationInbox`
and `exportActualPredictions`. An explicitly selected synthetic/evaluation store
is passed to the read-only capture helper with `optIn=true`; it never opens an
account directory. Capture immediately before/after the closed observation window
using `store.listMailboxMatches()`. Only mapped corpus publication notices enter
the snapshots; `excludedRows` records the count skipped without personal content.
Snapshot signatures verify notice payloads, **not** collection origin, trustworthy
wall-clock timing, model execution, or completeness. Imported JSON and its hashes
cannot prove those facts. Export is always `complete:false`, `k5Qualified:false`.

Freeze the exact manifest bytes and publish its SHA256 before capture. Schema v1
contains `runId`, `configSha256`, `frozenAt`, `designatedEvaluationCorpus:true`,
`codeSha256`, `modelSha256`, a single `scope` (`groupId`, `algorithm`, `bits`,
`epoch`), `window` (`start`, `end`, maximum24h), and `bindings`. Each binding is
`{role:'query'|'publication', corpusId, record}` with the exact signed public v2
publication record. Publication ID, sequence, signature, item type, group and
fingerprint epoch bind the join. Duplicate/revised corpus bindings are refused.
The manifest only designates test artifacts; it never proves a record's semantic
relationship to corpus text or that the claimed model/code produced its hash.

Capture schema v1 has `runId`, `manifestSha256`, `baseline`, `end`, and `searches`.
Snapshots contain `runId`, `manifestSha256`, `capturedAt`, `notices`, `excludedRows`.
Search entries contain `queryId`, `eventKind:'ephemeral-search'`, `observedAt`,
`threshold`, `k`, `results`; `results` is the existing `MatchingEngine.search`
array (`did` is runtime publication ID, `itemType`, `similarity`). Store the
actual returned results; publication-match events are not search responses.
Threshold must equal the frozen candidate threshold; `k>=5`. Score checks compare
against signed mapped fingerprints. Capture one search per query; no silent old
run mixing or duplicate result joins. Every mapped end-snapshot notice must have
a consistent scored result or export fails; actual notices cannot be silently
omitted because they are absent from the ranked candidate capture.

New stable match IDs in the end snapshot count as the current v2 inbox notices
shown before true-vector confirmation. Existing baseline IDs do not count again;
missing baseline rows refuse export. Actual store own-item suppression and relay
retry deduplication happen before capture. No absent, failed, cancelled, pending,
foreign or unscored pair becomes `false`. Scored pairs without a newly stored
notice remain `notified:null`. Notification FPR excludes null decisions; candidate
FPR retains scored known negatives as its distinct denominator. Legacy boolean
judged inputs remain accepted. Snapshot deletions/reinsertions, multiple scopes,
epoch migration, false-decision completeness and below-threshold/top-k ranking
coverage remain unqualified. Strict keys and bounded artifact sizes prevent
unexpected fields being propagated.

## Offline bilingual judgments (schema v1)

The existing runner also accepts externally collected judgments and final pipeline
predictions. This mode performs no embedding inference and never qualifies all K5:

```sh
npm run eval:scoped-fingerprint:real -- \
  --judged-input /absolute/input.json \
  --frozen-config /absolute/frozen-config.json \
  --config-sha256 PREVIOUSLY_PUBLISHED_SHA256 \
  --out /tmp/k5-quality.json
```

`--enforce` always exits1 for judged input because independent-data audit, privacy,
rotation and migration qualification are not implemented by this offline report.
Outputs refuse overwrite. Input limits are32MiB/config64KiB,10,000queries,
100,000publications and1,000,000 judgments/predictions each. Supply local files;
this command does not create a corpus or assert that supplied labels are independent.

The exact types live in `packages/eval/src/fingerprint-judgments.ts`:

- Config: `{version:1, frozenAt, testOpenedAt, seed, candidateThreshold,
  corpusSha256, judgmentsSha256}`. Times are ISO timestamps. Threshold is in[0,1].
- Input: `{version:1, corpus:{queries:[],publications:[]}, judgments:[],
  provenance:{assessor,method,independentOfEmbeddings,fixtureOnly,
  positiveInventoryComplete}, predictions:{generatedAt,configSha256,pipeline,rows:[]}}`.
- Each query/publication: `{id,language:"es"|"en",text,topicGroup,
  paraphraseGroup,split:"development"|"test"}`. IDs are unique within each collection.
  Group IDs must identify semantic topics/paraphrase families across both languages;
  translators must reuse group IDs rather than invent separate translated families.
- Each judgment: `{queryId,publicationId,relevant:boolean}`. Each scored decision:
  `{queryId,publicationId,score,notified:boolean}`. Score is in[0,1]; notified means
  the final notice a user would receive after the actual confirmation/filter path.
  Record `false` decisions too: absent decisions are unknown, never true negatives.
  Specify the real model/configuration/code/export provenance in `pipeline`.

Use exported `contentHash(value)` (SHA256 of UTF8 `JSON.stringify(value)`) for
corpus/judgment digests; preserve array order and object key insertion order.
Use `bytesHash(configBytes)` for the exact config file and prediction binding.
The caller must publish this digest in an independent dated record **before**
opening held-out tests. Freeze before test opening, generate predictions afterward,
and record that same config digest with them. The command detects inconsistent
hashes and dates; it cannot prove that a caller did not rewrite all inputs/dates.
Supplied provenance and freeze remain self-declared until external review. A hash
computed after seeing predictions is not evidence of a predeclared threshold.

`topicSplit(seed,topicGroup)` deterministically selects test when the first32 bits
of SHA256(JSON.stringify([seed,topicGroup])) divided by2^32 are below0.2; otherwise
it selects development. Freeze the seed without inspecting outcomes. Never reroll
seeds to select easier tests. The reader refuses wrong topic splits and normalized
identical text or declared paraphrase families crossing splits. Semantic leakage
still requires human review; metadata cannot detect undeclared paraphrases.
Judgments/predictions may reference only same-language test queries/publications.

Per language, Recall@5 counts retrieved known relevant publications over all known
relevant publications (micro recall); all known targets contribute, not just one
chosen target/query. A separate macro query recall averages each query's recall
among queries with known positives; excluded zero-positive queries are counted.
Neither aggregation is asserted to be the accepted K5 threshold definition.
Ranking uses all supplied scored publications, descending
score with publication-ID lexical ties, without a threshold. Omitted publications
are unretrieved. Reports show queries without known targets or predictions;
unknown positives make recall conditional. Final-notice precision has both a
judged-only estimate and a conservative known-true/all-notices bound, with explicit
unjudged notice counts. Candidate precision/recall/FPR remain separate. FPR uses
known negative pairs with explicit decisions; the report includes total known
negatives, all possible same-language test pairs and judgment/decision coverage.
Unjudged cross-pairs never become negatives. Known false notices/query is a lower
bound if notifications are unjudged; it has no K5 acceptance target of its own.
Topic-cluster bootstrap intervals use200 deterministic resamples; fewer than two
topics yield null. They describe the observed sample and do not correct incomplete
labels, convenience sampling or dependence between mislabeled topic groups.

Before a K5 campaign, obtain independent ES/EN relevance assessments, review
complete positive inventories and negative sampling/population, audit topic and
translated-paraphrase separation, preserve the pre-test config publication, and
export real final notification decisions (not thresholded candidates). The report
always leaves K5 false: >=1,000 queries/>=10,000publications, both-language coverage,
Recall@5>=90%, notified precision>=80%, FPR<=5%, <=5-point rotation loss, separate
<=5% reconstruction/known-text attacks and gap/duplicate-free epoch migration all
need adequate evidence. Do not tune on held-out failures or reuse this unit fixture
as development or qualification data. Historical failed attacks below remain valid.

### Notification measurement boundary clarification

K5 already measures notifications users receive. The exporter should therefore
measure actual v2 inbox insertions as the current notification boundary, including
notices preceding vector confirmation. A future confirmed-only inbox is a product
change, not a choice that can improve this evaluation by excluding current notices.
Confirmation outcomes may be exported separately; no new owner decision is needed
merely to measure the current visible behavior. Absent/pending/failed pair decisions
remain unknown, not negative. Exporter remains unimplemented.
