# Retained generation routing and resumable owner download

Status: **experimental historical evidence APIs, 2026-10-16**. This extends
[generation provisioning](v0.4-history-provisioning.md). It does not restore a
live admission ledger or certify that a downloaded history is currently freshest.

## Serve the enrolled chain

`createHistoryGenerationReplica` accepts `ancestors`, ordered from genesis to
the generation immediately before its configured parent. The adapter validates
the entire chain before opening its provisioning journal: member/context pins,
unique roots, each continuation's exact predecessor, and durable activation in
that predecessor. A gap, wrong-member store or absent genesis refuses setup.
The existing maximum is 65 generations (64 continuation links).

The same bounded checkpoint endpoint can read every enrolled generation and the
ready child. Ancestors remain caller-owned open stores; the adapter owns only
their signed exchange roles. Provisioning and agreement still target the one
configured current parent. Remote callers cannot enrol paths, replace the map
or discover an unconfigured store. Serving a longer chain requires its retained
handles; it never reconstructs missing published histories.

## Download a selected history

`createHistoryAncestryDownload` takes an independently retained, owner-signed
successor proposal, the context/owner key and five pinned member endpoints.
The proposal's four frozen receipts anchor one selected current-generation head
and any shorter frozen prefixes. This can be a historical selection; it is not
required to be an already confirmed successor decision because the API only reads.

The owner requests the exact selected head and follows signed predecessor hashes
backwards. Every returned envelope must have the expected digest, generation and
sequence, even if its owner signature and responding member's signature are both
valid. Each shorter freeze anchor is checked at its sequence. Reaching sequence
zero must reach the pinned root. A continuation root authenticates its own four
confirmed votes and predecessor proposal; downloading then continues from that
proposal's selected head. Completion requires reaching genesis through every
intervening block and boundary.

One authentic source is enough to supply a particular immutable block after its
identity has been anchored. The owner tries all five pinned sources and cancels
unused requests after the first verified response. It does not count these reads
as votes, freezes or current write readiness. Sources can hold later compatible
history; only the selected immutable prefix is returned. A different authentic
branch is rejected, and unavailable selected ciphertext blocks progress.

## Durable bounded progress

Each immutable ciphertext block is flushed and renamed before its digest enters
the atomically replaced encrypted owner manifest. The manifest binds the exact
independently supplied proposal and the descending digest list. Reopen verifies
every indexed file and re-derives the traversal position from the signed chain.
It never trusts a saved cursor without replaying that validation.

A process can die after a block is durable but before its index entry. Only the
exact next expected block may remain unindexed. Reopen verifies it; a subsequent
explicit run indexes it without fetching it again. Unknown block digests, changed
selection pins, missing/corrupt indexed files and malformed pending blocks refuse
progress and remain on disk. Uncommitted temporary write files may be removed
under the manifest lock after validating retained state. An uncertain write
poisons the handle until close/reopen. Initialization is explicit and requires
an empty directory; reopening missing state never creates a new download.

Limits are 10,001 blocks across the whole selected ancestry, 64 MiB of encoded
blocks per generation, 256 MiB total including two 2 MiB manifest allowances,
and 64 continuation links. The block/total-byte limits can be reduced by the
caller. Hitting a limit keeps all progress and never reports completion. These
are cache/file bounds, not whole-process memory or physical-disk guarantees.
The aggregate block limit can refuse a lineage whose individual stores fit;
safe compaction is still required before indefinite operation.

Each explicit `run()` processes at most 64 missing blocks by default (caller
bound 1–10,001) and has a whole-attempt deadline of at most thirty seconds,
including cryptography and persistence. Cancellation/close abort pending socket
requests. A transport that ignores cancellation cannot hold the returned promise
forever. Reopen, status reads and iteration perform no network requests.
`blocks()` yields the completed ciphertext in chronological order, one block at
a time; incomplete downloads cannot be consumed as a complete recovery image.

## Validation

The tests cover persisted prefix resume, source loss, malformed replies, validly
signed unselected blocks, independent selection mismatch, indexed corruption,
missing files, capacity refusal, failed fsync, deadlines, cancellation and
overlapping attempts. Five SIGKILL cases interrupt block publication and index
replacement before/after rename or after durable progress; authentic unindexed
blocks are adopted without network repetition.

A network scenario serves genesis and two certified successors on five real
loopback endpoints. It writes the newest generation, freezes/selects it,
downloads two blocks, closes/reopens the owner and disconnects four services.
The remaining service completes the old-generation traversal. The chronological
result contains all three roots and both intervening deltas. Enrolment refuses
missing genesis and wrong-member ancestry before creating its directory.

TypeScript compilation passed. The initial focused run passed 44 tests across
five files before the final unselected-block case and traversal optimization.
The final complete suite passed **140 files / 838 tests** in **456.29 seconds**,
with one worker. All **336 TypeScript source hashes** stayed unchanged during
that final run. These are local implementation results, not independent-network
or physical-power validation.

## Compose retained data with agreement

`coordinator.select()` runs only the four-report promise phase and persists the
actual selected proposal and view certificate. It sends no prepare/confirm
requests. The selected proposal can differ from the preferred one when a report
carries an earlier prepared value. Choose the downloader's proposal from this
durable result, then download explicitly in bounded steps. Reopening the
coordinator or repeating `select()` after selection sends no traffic.

Configure `historyTransfer.retained` as a callback returning the completed
downloader's `blocks()` iterator. `run()` revalidates signatures, the exact
current-generation chain, its selected root/head and every shorter freeze anchor
before preparing any member. It bounds traversal to 10,001 records / 256 MiB,
with at most 64 MiB in the selected generation. It does not silently truncate
extra current-generation blocks, fill gaps or fall back to a different source.
Incomplete downloads refuse preparation; an explicit later retry can use the
same cache after completion. The existing thirty-second agreement deadline
includes traversal, cryptography, write-back and votes.

Cached ciphertext only replaces network reads. The coordinator still performs
authenticated head/stage transfers where needed and obtains fresh prepare/confirm
responses. If another coordinator has raised the promised view during download,
the obsolete attempt cannot use its cache to bypass that barrier. A later view
requires explicit `beginView()` and a new selection. Cached selection/decision
evidence is historical; it never certifies current availability.

The composition tests cover hidden carried decisions, caller mutation, reopen
without traffic, incomplete/extra/corrupt retained data, close during traversal
and a higher competing view. A real-socket test pauses a download, reopens both
owner and cache, finishes it, repairs a different fourth volunteer and confirms
without re-downloading the retained ciphertext. The focused agreement/coordinator
suite passed 20 tests; the subsequent writer-repair group passed 30 tests across
three files. Complete regression validation is recorded in the completion plan.

## Remaining operational composition

The writer can now [repair live suffixes](v0.4-history-checkpoint-exchange.md)
from an explicitly retained current-generation prefix. The subsequent
[retained writer](v0.4-history-writer-retention.md) adds a complete durable owner
payload journal and indexed repair. Integrating quorum replication before real
admission acknowledgements remains open. Then implement reviewed, freshness-checked atomic restore and
quorum-safe compaction. Historical completeness by itself cannot authorize a
lost ledger to accept new tokens, erase permanent denials, or replace the latest
accepted history. Existing split legacy reservations remain unchanged.
