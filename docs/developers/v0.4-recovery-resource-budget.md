## Accounting rules

Core anchors: `packages/core/src/storage-reservations.ts:15–19,65–76,131–147,272–295`
and `storage-reservation-context.ts:4–45`.

- Authority control peak is 2,105,344 bytes, including two 1 MiB ledger images and
  8,192 ownership bytes. Entry cap counts allocations PLUS adoptions; this fixture
  has zero adoptions. Metadata also has an independent 1 MiB serialized limit.
- Identity is canonical absolute path plus fixed component/scope. Repeated
  reservation of that identity raises its byte maximum monotonically and consumes
  no new entry. A new path consumes another entry, even after deletion or failure.
- Encrypted file F is one `encrypted-local-state`/file entry with peak
  `2 H_F + 8192`. Its ownership directory/claim and old/new atomic images are
  included; do not count an extra lock entry. Standalone ownership without an
  included lease is `local-state-lock`/file, 8,192 bytes. Source:
  `local-encrypted-state.ts:38,63–66,206–214`.
- Fixed files use their encoded ceiling as H. Opted NEW files persist authenticated
  `monotone-v1`, canonical path, component, authority ID, ceiling and high water.
  `Hnext=max(Hprevious,current encoded length,all promised completion bounds)`.
  `encryptedLocalStateByteBound` is `ceil((JSON bytes+extra)*4/3)+8192`, with
  wrapper/binding headroom; this is a conservative encoded bound, not plaintext
  size. Reserve before pending intent/external effects, obtain fresh leases after
  growth, and retain failed growth charges (`local-encrypted-state.ts:20–24,38–82,179–201`).
- Immutable history has TWO entries: a directory component
  (`history-replica-ciphertext`, `history-writer-ciphertext` or
  `history-download-ciphertext`) plus encrypted manifest/file. Serial rename moves
  the same block inode, while old/new manifests remain charged separately.
  Downloads are separate retained copies, never free deduplication. Source:
  `packages/relay/src/history-storage-reservation.ts:1–16,24–50`.
- Immutable operator JSON is one `operator-output`/file at actual JSON+newline
  bytes. Atomic settings are one `operator-atomic-output`/file at `9 M+8192`
  (eight retained/interrupted replacement slots plus primary); ownership included.
  Source: `admission-operator-files.ts:45–74,89–123`; handoff actual-size export:
  `witness-handoff-command.ts:18–28`.

Thus full peak is `control + sum(old committed maxima) + sum(new directory block
peaks) + sum(new encrypted 2H+8192) + sum(new immutable output lengths) + sum(new
atomic 9M+8192)`. Each term stays charged after crash or refusal; no subtraction
for cleanup. A bound for each simultaneously retained/future promised image is
required before this equation proves fit.

## Candidate subordinate mechanism: prospective complete-scope funding

Reject a transparent adapter that simply maps every child request to one
same-sized directory request. Existing directory leases check one output against a
maximum, not the sum of all descendants. They also reject file-style atomic
replacement through a directory lease. `reviewScope().reserved` is coverage
metadata, not proof that all children fit. Existing API can express ONE aggregate
directory reservation; it cannot by itself express enforced child delegation and
aggregate accounting. No safe grouping implementation is approved by this report.

One candidate resource contract within a complete recovery design is ONE
independently selected NEW
lifecycle scope with a finite deterministic layout and precomputed complete sum of
all disjoint child obligations above, including separate output files and download
copies. Reserve its aggregate maximum through the ORIGINAL authority's existing
directory entry before any intent, freeze or provisioning. Bind scope, authority,
mode, ceiling, layout version, child identity/slot and promised peaks into existing
authenticated owner state. An owner-exclusive delegated writer must enforce that
each write fits its nonoverlapping slot, including old/new snapshot and interrupted
output allowances; a child cannot authorize itself from a peer descriptor or
reset its slot on reopen. Aggregate growth commits original authority funding
FIRST, then durable authenticated obligation, then effects; failure retains the
larger charge. Captured asynchronous operations retain the same parent scope and
authority. Reopen independently selects authority/scope, verifies the existing
aggregate reservation and every retained child/temporary/pending obligation;
it neither allocates missing funding nor trusts a child-supplied maximum.

This must derive slot obligations from authenticated existing state and fixed
schema/layout; if it needs a separate persistent mutable child allocation ledger,
it violates the no-parallel-ledger constraint and is rejected. Existing-state
changes and delegated replacement semantics require architecture review before
code. It is UNKNOWN whether a sufficiently small complete static slot sum fits.
Grouping gives `E=Eold+G` only for wholly NEW scopes; it cannot absorb old paths,
refund old reservations, or retrofit the stopped512-entry authority. A fresh
prospective trial still pays the unchanged old baseline and every new disjoint
scope. G must include separately owned remote replicas/outputs outside an owner's
scope. There is no demonstrated complete G/count/byte upper bound yet.
