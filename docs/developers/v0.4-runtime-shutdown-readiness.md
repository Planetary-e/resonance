# Relay shutdown at the first readiness marker

The Linux job in CI run `39112734413` failed the protected-history process test:
after observing `started`, it sent SIGTERM and received exit code `null` instead
of `0`. The other 2,738 tests passed; the quick evaluator did not run because
the test step failed. This was separate from that run's Windows ownership failure.

The relay listener emitted `started` inside `server.start()`, while the runtime
installed SIGTERM/SIGINT handlers only after awaiting that method. A parent
reacting to the marker could therefore terminate the process before graceful
shutdown was registered. A dedicated preload fixture now signals the process
synchronously on its first `started` output: both SIGTERM and SIGINT reproduced
signal termination before the fix.

The runtime installs its handlers before starting the listener. Shutdown waits
for listener initialization to settle before draining, so timers cannot appear
after teardown. Concurrent shutdown requests share one promise. If shutdown
starts during listener initialization, later observer/contact startup cannot
overtake it. Existing accepted-work drain and key-cleanup order are preserved.

Both deterministic signal cases and all six admission-history configuration
cases pass: eight tests in 3.81 seconds. The tests assert normal exit code `0`,
no terminating signal, and the `stopped` marker. They are skipped on Windows,
where Node's process termination semantics differ. Local reproduction establishes
the race and correction; a new Linux CI run must verify the full checkpoint.
