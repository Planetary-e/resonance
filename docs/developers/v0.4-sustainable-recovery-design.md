## 1. Objects and authentication, without recursive replacement originals

All NEW wire frames use a versioned canonical binary encoding: unsigned integers
are u64 (reject overflow); digests/public keys are 32 bytes; Ed25519 signatures
are 64 bytes; enums u8; counts u32; variable bytes have u32 length. Domain and
version are explicit. Legacy originals remain their exact original bytes and
original signature/digest domains. Re-encoding an original never changes its ID
or authorizes a new signature. The following are maximum NEW fixed headers,
including reserved format bytes, not claims about current JSON sizes.

| Object | Fixed bound | Contents / cardinality |
| --- | ---: | --- |
| ObjectRef | 96 B | original domain/type, digest, exact byte length, privacy scope ID; scope dictionary resolves authorized location/key context |
| ArchiveFrame | 256 B + payload | exact original bytes OR new signed object; object ID, original context/configuration/owner, sequence; no embedded prior image |
| SemanticRow | 2,048 B | typed key, original issuer/spend/action/binding digest, status, original-local owner/context/result reference, policy/configuration references; at most16 direct proof references; variable original values remain in archive |
| CutHeader | 1,024 B | original genesis/context, role, predecessor cut, sequence/view, terminal proposal/head, state root, proof-index root, configuration/policy floor, suffix boundary, layout/funding commitment |
| CutCertificate | 1,536 B | CutHeader + four distinct member IDs/signatures, each over exactly that header; IDs are pinned by authenticated configuration |
| ControlRecord | 16,384 B | one transition/checkpoint/view-change summary with bounded references; oversized attached evidence is separately charged ArchiveFrames |
| SuffixSlot | 16,384 B | one committed command header plus references; actual original payload is separately charged once per physical copy |

ControlRecord and SuffixSlot have at most128 direct references; additional proof
bundles are separate charged ArchiveFrames. SemanticRow has at most16 direct
references; a typed proof-bundle reference can name a larger complete closure,
whose bytes/count are charged separately. Existing per-table10,000-row limits
remain; total rows across distinct tables/scopes are independent forecast inputs.

These headers are a proposed format contract, not permission to truncate long
originals. A field that cannot fit is represented by a typed ObjectRef, including
length and original verification domain. A proof object may reference other
objects but never expand an old state tree. New proof dependencies are either
original leaf objects, a prior certified state header, or configuration edges.
Business-state roots cover sorted rows; exact equality uses canonical bytes,
not locale-dependent sorting. Hash collisions are outside the existing
cryptographic model. Completeness is established by execution below, not Merkle
membership alone.

Archive keys include original context and digest; deduplication is allowed only
for identical bytes in the SAME physical/privacy scope. A ref shared by 100
transitions is one object per required physical copy, not 100 nested histories.
Independent consumer pins, original configuration/key membership, terminal pairs,
manifest-v2 original commitments and every required historical proof remain
available. Existing originals are never deleted on the strength of this design.
New compact statements cannot retroactively turn old owner strings into proof.

## 2. What is certified and how agreement obtains it

### Bootstrap once; thereafter validate executed transitions

The first cut requires the existing complete original verification/reduction for
each selected old logical owner's terminal history, independent consumer pins,
policy archive and exact selected storage head. Four independently verified
terminal reports need not be identical. Their proposal/context must match and
each must carry its own four-storage-replica terminal barrier. A missing original
or inability to finish within the existing operation budget refuses bootstrap.
There is no shortcut for legacy migration through a self-signed snapshot.

The selected logical witnesses deterministically construct the union of valid
original votes, genuine certificates, proven original-local acceptance, denials,
fences, inherited rights and unresolved claims. Each honest signer requires the
union to contain its complete protected evidence floor, including emitted but
unanswered votes. Each addition must have the same original semantic proof that
full replay required; an owner label or Byzantine report cannot add acceptance,
policy denial or rights. A Byzantine member may withhold its own evidence;
it cannot prove global absence. Four old vote signers and four reporting owners
intersect in at least three members, at least two honest, so a hidden genuine
four-vote certificate leaves an honest protected binding in the terminal union.
This argument covers quorum-certified admission. It does NOT certify an absent
owner's private wallet state, issuer ledger or local-only spend; those remain
separate owner recovery obligations.

Each honest old logical witness then signs the SAME deterministic union cut only
after validating all proof additions and its own floor. Thus four signatures
certify one interpreted state, unlike four unrelated local report hashes.
Inconsistent valid claims are retained with `UNCERTAIN_CONFLICT`; no fresh spend
is issued for that key. A valid original certificate can resolve compatible
partials to its original binding; incompatible certified outcomes halt with
evidence. Neither timeout, missing fifth member, expiry of a live lease nor
absence of an assembled certificate releases a reservation.

### Ordered protocol, including concurrent checkpoint and reconfiguration

After bootstrap, logical witnesses run a PBFT-style authenticated state-machine
instance per existing admission authorization scope. Membership remains five,
prepare/commit/view-change quorums are four. At `(configuration, view, sequence)`:

1. Leader proposes command, predecessor committed digest, original proof refs
   and deterministic resulting state root. Each member fetches and validates
   necessary original additions and checks policy/freshness and resource promise.
2. Persist PREPARED only after four matching signed prepares. Persist COMMITTED
   only after four matching commits for that prepared value. Execute in sequence;
   retain the original accepted result before exposing any reply or vote.
3. Each signed view-change record carries its verified four-signature stable-cut
   certificate (or the original authenticated bootstrap base), the durable
   committed `(configuration, sequence, digest)` floor and prepared certificates
   above that base. A bare sequence number cannot advance the base. From four
   such records, deterministically select the highest valid authenticated
   checkpoint base; incompatible certified bases halt with evidence. Fetch and
   verify that base's matching state/proof closure before participating, never
   regress below locally durable committed knowledge, then select the highest-
   VIEW prepared certificate for each sequence above the selected base. A new-
   view message contains those records and the exact deterministic selection.
   Honest members reject omitted/changed protected values. No proposal is accepted
   solely on leader assertion. Uncommitted slots carry forward; no skip over a
   committed predecessor. Referenced certificates and proof bundles remain fully
   available and charged even when retired live prepared records are absent.
4. A cut is a committed control command. Members sign the CutHeader only after
   executing through its sequence, retaining the exact state/proof objects and
   funding their completion. Four identical signatures make a stable cut.
   Retire live journal slots only after durable cut and required archive copies;
   retired journal protocol messages do not authorize deleting originals.

This is the protocol contract to implement/review, not a claim that arbitrary
four signatures implement PBFT. Durable non-equivocation, correct new-view
selection and external-output ordering are essential. Honest quorums intersect
in at least two honest members; honest members never commit two values at a
sequence or sign a second successor from the same terminal cut.

Bound the working suffix to **32 command slots**. At 24 occupied slots initiate
a checkpoint; reserve the remaining eight for the declared burst/control
completion. Serialize control work and stop admitting new commands when the
32-slot promise would be exceeded. An already accepted command always owns its
completion slot. Two concurrent operations and eight-request bursts do not
permit unbounded pending queues or reset original deadlines. Capacity refusal
is counted as an operation failure, never as successful KPI service.

## 3. Handoff, private roles, restart and currentness

Reconfiguration is a committed command in the same order as admission changes.
Bind exactly one successor configuration, terminal cut and original proposal.
Stop old admission, settle or explicitly carry every pending obligation, then
under each owner lock run the existing four-storage-generation freeze and
compare its exact selected head. A changed selected head must be reconciled
before signing; no post-cut old work is silently ignored. Freeze uncertainty
persists serving refusal, including unrelated work on that frozen shared history.

Use the existing sealed-observer/current-policy path and full three-second
authorization drain; restart repeats the wait. Four successor logical witnesses
independently validate genesis-to-current configuration authority, cut certificate,
state bytes and required original additions, store the state and proof closure,
and sign readiness for exactly that cut/proposal/floor. Activation requires the
old cut certificate, terminal pairs, observer seal/drain and four successor
readiness records. Persist activation/freshness floor before serving. The
30-second offline-preparation allowance never extends live authorization.

Repeat the SAME protocol for a second disjoint successor. Its state preserves
original object IDs and original-local acceptance owner/context; an imported
accepted row is never relabeled as accepted locally. Exact retry returns the
original result after checking its original authenticated acceptance provenance.
New policy authorizes new work; original policy proves retained rights/retries.

Issuer counters, issuance reservations and pending emissions use the issuer's
existing authenticated protected owner state; wallet token ownership, spent
status, proof catalogue and pending redemption remain under wallet keys. Their
new local snapshot covers these fields and is linked to the verified prior state
and bounded owner journal. An honest owner may restore its own authenticated
execution state with its existing key and current quorum/head checks; admission
witnesses do not certify hidden counters or get those keys. Any assertion used
by another role still supplies its existing issuance/redemption proof. A
malicious issuer/wallet cannot gain additional authority through a local cut.
If a particular issuer-loss path currently requires independent proof, its
original proof remains required; this design does not close K4 issuer loss.

Returning owner startup has ONE verified entry point, used by CLI and service:
independently select owner key/genesis/pins/authority; validate current activation;
retain the independently authenticated protected-head selection and durable
`(configuration, sequence, digest)` knowledge floor across the replacement. Bind
the selected protected endpoint to its exact semantic cut/sequence/state root.
The cut plus contiguous suffix must reconstruct THAT independently selected
endpoint while preserving local pending/prepared evidence, not merely a valid
earlier endpoint in the same configuration. Fetch/catch up or refuse if the
endpoint or durable floor is not reached; policy freshness alone cannot prove
completeness after a later spend. Restore private owner state and original
retry catalogue; prepare authorized history continuation; initialize the policy
mirror from the exact authenticated installed policy/floor; persist mirror and
owner state as one recoverable installation intent; reopen both and compare
floor/root; obtain current freshness before publishing readiness. An incomplete
mirror/install refuses service and resumes the SAME funded intent. Do not leave
CLI on direct `openProtectedAdmissionSpendHistory` while services use a different
factory. This explicitly repairs the audited owners1–4 functional omission.

## 4. Cold genesis, compaction and permanent archive

A cold genesis-only participant verifies each signed configuration transition
from original pins, including old authorization, cut, terminal/drain and new
readiness/activation. Verify iteratively; reject epoch reuse, forks and missing
edges. Its latest usable cut is then authenticated by that chain. It requests
fresh current authority before serving; a valid stale chain is insufficient.
Existing freshness prevents a retired-key history from silently becoming current
under the unchanged non-mobile fault model.

The NEW semantic compaction anchor is a stable cut plus its configuration proof
index. After it is installed, active business ancestry starts at that anchor and
has at most32 suffix commands. Retain every older configuration edge and original
proof in a flat archive; crossing64 configurations does not create a recursive
65th history ancestor. Authenticate before shortening the active path. Do not
disable existing 64-depth or128-transition guards for legacy objects. The new
versioned iterative verifier checks the complete finite configuration chain;
its bound is an explicitly funded object count/byte/work budget, not a hidden
unlimited recursion change. At100 transitions there are101 configurations.

Hot operations read the current indexed row, necessary proof closure and bounded
suffix; they do not scan/reconstruct the cold archive. Cold genesis needs O(n)
configuration checks, not O(n) business images. Local reopen validates the
authenticated index and selected objects lazily, with missing/corrupt proof
refusing the dependent action. Required archive copies must remain accessible;
merely saving hashes does not meet this requirement. Full migration bootstrap
can still exceed256 MiB and must be costed separately.

## 5. Fixed allocation contract for deterministic forecasting

All figures below are additional to any retained legacy reservations. A new
layout version uses fixed, independently selected owner/replica roots for all
generations. No per-cycle directory, complete restore tree or repeated exported
original bundle is created. CLI exports are small manifests referring to the
funded archive; an actual standalone export copy is an additional obligation.

For the audited fixture freeze the physical scope inventory as **17 local owner
scopes** (five observers, ten witnesses, issuer, wallet), **80 replica scopes**
(five per16 protected owners) and **one operator/control scope**: G=98 NEW
authority entries, constant for two or100 transfers. Wallet is local here;
additional wallet replicas, new physical owners or standalone exports must be
explicit forecast inputs, never silently included in98. Disjoint *logical*
cohorts use the ten existing witness-owner slots; more distinct physical owners
increase the scope count. No key/context reuse is implied by physical slot reuse.

Each scope has a statically partitioned arena. The original resource authority
reserves its complete peak once. A delegated writer derives non-overlapping
offsets/slots from authenticated layout and object IDs, enforces aggregate sum
and atomic replacement inside its own slots, and captures the same authority
for asynchronous work. Funding precedes durable promise, which precedes effects.
Reopen independently verifies authority/scope/layout and all promised slots.
There is no new financial ledger: object index and pending intent are application
state; the original authority remains sole funding truth. Failed reservations
and abandoned immutable frames stay charged. Generic directory leases alone
cannot implement this proposed delegated arena.

Use these finite inputs; bytes are PHYSICAL encoded bytes including encryption,
framing and retained temporary copies, not plaintext estimates:

- `N=2 or100` transitions; `R=5 or250` returning-owner installs (250 is the
  explicitly frozen repeated two-transfer pattern, not a measured campaign).
- For each owner `i`, `L_i` maximum encoded live state/index, `D_i` maximum
  total encoded 32-slot suffix, `P_i` encoded pending completion/install state,
  `C_i(N)` all distinct retained cold original/proof frames, excluding ONLY
  the particular control/config slot capacities prepaid in `K_i`. Additional
  view-change, checkpoint, configuration or protocol frames beyond that declared
  allowance MUST be charged in `C_i` with their complete proof closure. They
  cannot be omitted or implicitly treated as failed/unindexed append data.
  `L_i` includes policy mirror, private counters/catalogues and conflict/denial
  rows applicable to that role. NO per-return full snapshot in `C_i`.
- `F_i` encoded failed/unindexed append frames retained across the finite
  1,000-fault scenario manifest. A crash at each retry is separately charged;
  same identity resumes its slot. 1,000 faults alone does not bound frame bytes.
- `X` every standalone output/export/import copy plus their interrupted images;
  zero only if the declared workflow truly uses references into funded arenas.
- `K_i` NEW flat control/config frames, bounded by `16,384*(N_i+R_i+2)` per owner.
  Freeze `N_i=N` for every owner (conservative policy/configuration continuity);
  only witness owners1..5 have returns, each `R_i=R/5` (1 or50); all other
  owners have `R_i=0`. Each returning owner has five replicas. This assigns
  each return to its actual six physical copies, not all owners. If the protocol
  emits more than one such frame per listed event, include the extras before use.

For each local scope reserve
`A_i = 8192 + 2*L_i + 2*D_i + 2*P_i + C_i(N) + F_i + K_i`.
For each of five replica scopes of protected owner i reserve the SAME `A_i`
as a conservative complete-copy envelope; implementations may subsequently
prove smaller role-specific copies, not assume them now. Wallet has one copy.
Operator scope reserve `A_op=8192+X+16,384*(N+R+2)`.
Thus `B_new = 6*sum(A_i for16 protected owners) + A_wallet + A_op`.
Cut certificates and original pins are in `C_i`/`K_i`; fixed suffix and atomic
old/new state are in the doubled terms. Owner locks are8192 per physical scope.
This complete-copy conservative formula intentionally counts 98 physical scopes;
it does not deduct an imagined shared archive across privacy scopes.

`E_total=E_old+98`; authority control peak remains2,105,344 bytes and is included
in measured `B_old`, or added once for a genuinely fresh authority. Serialized
authority metadata must be measured/bounded separately: reserve no more than
1,024 encoded bytes per NEW entry, including canonical path/component/scope,
plus actual old serialization and top-level overhead. G adds at most100,352
bytes, but old metadata size is UNKNOWN. Long paths fail the prospective layout
before commitment; no original path is renamed to manufacture this bound.

## 6. Work/time envelope and acceptance boundary

Per operation carry ONE cumulative work meter through all nested decoders and
copies. For selected encoded state `L`, suffix `D`, new proof closure `V`,
configuration chain `H`, and verified-bootstrap original material `J`, freeze
the implementation target `W <= 4*(L+D+V+H+J)` bytes, where four is a proposed
maximum number of materializations, not measured current behavior. `J=0` after
certified bootstrap; first legacy bootstrap includes its complete originals.
Require `W<=268,435,456` before effects; with this target the total selected
material must be<=67,108,864 bytes. Instrument every copy/expansion to validate
that four-materialization bound. A larger actual factor is a failure, not a
license to reset the meter. Repeated archive expansion is not permitted.

The3s live and30s offline bounds remain unchanged. No time guarantee follows
from byte arithmetic. The minimum unknown performance observation is one actual
crypto+disk+network cut/install at the MAXIMUM admitted finite envelope, including
cold101-configuration verification,32-slot suffix, current-policy startup and
restart-sensitive drain in its proper phase; separately measure initial legacy
bootstrap. This is a future bounded benchmark decision, not a100-cycle campaign
or permission to run it now. If worst-case input cannot satisfy the work budget,
do not benchmark a smaller unrepresentative fixture as evidence.

Acceptance gates, in order: complete finite physical-obligation manifest and
both forecasts; one critical protocol review; only then one coherent vertical
of certified cut→disjoint install→returning-owner policy/bootstrap service with
