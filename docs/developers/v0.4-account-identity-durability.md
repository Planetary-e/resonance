# Account identity validation and interrupted writes

The personal account identity remains an encrypted `identity.json`. Existing
versionless/v1 and Argon2id v2 exports remain readable. New exports use v2.
Import checks exact envelope/plaintext fields, canonical base64, bounded lengths,
the Ed25519 public/secret relationship and the DID derived from the public key.
Unknown versions no longer fall back to legacy decryption. Export validates and
copies the plaintext before asynchronous password derivation. Temporary derived
keys and byte buffers are cleared; JavaScript strings and runtime copies cannot
be promised complete memory erasure.

## Local publication protocol

Account operations hold the existing single-host PID/nonce ownership claim,
after resolving parent-directory aliases. Another cooperating process cannot
create, read or replace the account concurrently. Creation refuses existing or
interrupted account state. This also applies when the desktop's in-process guard
is bypassed by a separate process.

The primary is bounded to 4 KiB. A bounded 8 KiB `.pending` journal retains only
the intended encrypted export and the SHA-256 of its original primary, or null
for first publication. After flushing this intent, `.next` receives the exact
encrypted candidate and is flushed. First publication uses a non-overwriting
hard link; replacement uses atomic rename. The primary and directory are flushed
before removing recovery artifacts. New files use mode 0600. An explicitly
managed caller reserves the complete 24 KiB snapshot/journal/ownership peak at
the single-link intent path before writing.

Recovery authenticates the export with the password. An interrupted initial
publication can finish only the retained identity. An uncommitted password
replacement keeps the old primary authoritative; saving the same identity with
the intended new password resumes the exact retained ciphertext. A committed
replacement finishes cleanup after authenticating the new primary. No retry
creates a fresh key or silently substitutes a new ciphertext for a pending one.

A truncated intent cannot prove what was intended and is retained for inspection.
Missing or changed originals, divergent candidates, orphan temporaries, oversized
files, directories, symlinks and unexpected hard links are refused. The one
permitted two-link state is the exact primary/candidate pair during initial
publication. Failures never authorize deleting an existing account or its data.
The CLI no longer recommends removing the account directory to reinitialize.

## Evidence and limits

The focused group passes **78 tests in seven files**, including 21 actual SIGKILL
boundaries across creation/password replacement, four reported I/O failures,
three competing creator processes, corruption/alias/capacity cases, legacy
identity migration, database upgrade and the actual desktop HTTP login flow.
TypeScript passes. These account tests are also included in the lightweight
Linux/macOS/Windows CI matrix; native installers are not built by this matrix.

The SIGKILL experiments verify process interruption on a local filesystem.
They do not simulate physical power loss, hostile processes with the same OS
account, or a network filesystem. Windows flushes file contents but does not
perform the POSIX directory flush; its platform-specific CI remains separate
evidence. Windows skips the symlink privilege-dependent case and directory-flush
boundaries. Incomplete intents remain a visible recovery limitation rather than
being erased to make initialization succeed.
