# Separate-process reply-mixing experiment

Run: 2026-09-29T14:30:17.612Z; Node v24.19.0; darwin/arm64. Source base: 08e7e33de61e950fa1897838dc1557ef3ec2b91b. Experiment and queue changes are in the same commit as this report.

## Method and limits

8 logical clients each send one equal-size search per trial. The clients share the parent process; baseline entry, treatment entry, and destination each run in their own child process. Both conditions use the default client scheduler. Both entries mix requests using a 750 ms collection window. The baseline immediately returns each encrypted reply; the treatment collects replies in an independent 750 ms queue and shuffles their release. Mode order alternates across 3 trials per workload/network profile. Burst actions are scheduled 20 ms apart; sparse actions 1,000 ms apart.

The simulated network profile delays each outgoing application frame by 20–60 ms, using seeded per-process pseudo-random streams. The zero-delay profile is ordinary loopback. This models frame latency and reordering between independent short connections, not TCP packet loss, bandwidth, geographic paths, or TLS record sizes. Relays share a physical machine and host clock; traces use epoch timestamps with a 2 ms cross-process clock tolerance. Per-IP discovery/search limits are raised to 10,000/minute because virtual clients share an address.

The observer pairs timestamps by rank, without IDs, payloads, or sizes. Ground truth is kept only by the scorer. Forward accuracy compares entry ingress to destination ingress; reply accuracy compares destination reply send to client receipt. Transit latency includes queueing, cryptography, signing, and the simulated link. Full completion latency includes discovery. All requests must finish and have complete traces; failed trials stop the run. Crypto randomness is enabled, so exact measurements vary.

Random-pairing reference for 8 requests per trial: 12.5%; actual collection windows may contain fewer requests. Every request here uses one destination and one size bucket; batches split across destinations or sizes are not measured. Scores are a limited diagnostic, not independent statistical samples or an Internet anonymity guarantee. A stronger observer can use sizes, destinations, discovery, and repeated traffic. Colluding relays can still link the forwarded ciphertext and request ID.

## Interpretation

In this run, reply batching reduced the simple observer's loopback burst matches from 24/24 to 2/24. With simulated delays, burst matches changed from 5/24 to 6/24, so the experiment found no added benefit in that condition. Sparse replies stayed fully matched on loopback and changed from 20/24 to 24/24 with delays. These small samples do not establish a reliable noisy-link improvement or regression. Added median return latency was 0.73–0.77 seconds; full completion p95 reached 5.63 seconds for delayed mixed bursts. Retain the queue as experimental and leave production timing defaults undecided pending a sparse-traffic policy and stronger observer measurements.

Compare baseline and treatment under the same workload and network profile. Mixing may reorder a busy batch; it does not create other users in a quiet window. Reply scores isolate the added return queue; changes in forward scores between these two modes do not establish a benefit from reply mixing. Replies remain bound to their original request deadline, and admission failure never bypasses the queue. This experiment provides no cover traffic and no defense against colluding relay operators. Do not treat a low score for one attack as proof of anonymity.
